Course introduction

Who this course is for, what you need before you start, and how every page is laid out.

Who this is for

You write code for a living and you have an interview coming up. You can build a service, but it has been a while since you thought about why a hash map is O(1), or how to spot a sliding window problem in the first minute.

This course gets you back there. It is built for people who learn by seeing the data move, then reading the code that moves it.

What you need before you start

  • Comfort with one of Java, JavaScript, TypeScript or Python. Every solution is written in all four, so pick the one you will use in interviews.
  • Loops, functions, classes and basic recursion. You don't need any maths beyond school algebra; the course teaches the rest as it goes.
  • A way to run code. Each solution is a single file with its own main, so you can paste it into your editor and run it as is.

How every page is laid out

Each concept page follows the same order, so you always know where to look.

  1. Explanation. A plain-English description, with a concrete example before any theory.
  2. Picture. A labelled diagram of the structure, including how it sits in memory.
  3. Animation. A step-by-step demo with play, pause, step and speed controls. The matching line of code lights up as it runs. Where it makes sense, you can type your own input and run it again.
  4. Code. A full, runnable solution in your chosen language, with its expected output. Every sample on the site is run by an automated test.
  5. Practice. Problems to try next, from easy to hard, each linked to LeetCode.

How to use the site

  • Choose your language once. The language menu at the top changes every code block on every page, and the site remembers your choice.
  • Follow the roadmap. It orders the topics so that each one only depends on things you have already covered. Tick topics off as you finish them; your progress stays in this browser.
  • Predict before you press play. Before running an animation, guess what the next step will be. The guesses you get wrong teach you the most.
  • Solve before you read. On problem pages, try the problem on LeetCode first. Then read the brute-force approach, then the optimal one.

What the course covers

The course has five parts: data structures, algorithms, coding patterns, low-level design, and a practice index that collects every problem in one filterable list. The roadmap shows how they fit together and roughly how long each stage takes at a pace of 8 to 10 hours a week.
