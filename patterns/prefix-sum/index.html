Prefix sum

A prefix sum array stores running totals, so the sum of any range is one subtraction. Combined with a hash map, it also counts subarrays with a given sum in one pass.

Coding pattern

Picture it. A car's odometer. To find how far you drove between two towns, you don't add up every kilometre; you subtract the reading at the first town from the reading at the second.

Recognise it

  • Many questions about the sum of a range a[l..r] on an array that doesn't change.
  • Counting subarrays whose sum equals, or is divisible by, some k.
  • Balancing left and right totals: pivot index, equal partitions.
  • 2D versions: sums of rectangles in a grid.

The template

prefix[0] = a[0]
for i from 1 to n − 1: prefix[i] = prefix[i − 1] + a[i]
sum(l..r) = prefix[r] − (l > 0 ? prefix[l − 1] : 0)

Count subarrays with sum k:
    seen = {0: 1}; running = 0; count = 0
    for x in a:
        running += x
        count += seen[running − k]        ← earlier prefixes that leave exactly k
        seen[running] += 1

How it works

Once prefix[i] holds a[0] + … + a[i], the sum from l to r is everything up to r minus everything before l. Building the array takes one pass, and every query after that is O(1).

The counting trick turns that around: a subarray ending at i sums to k exactly when some earlier running total equals running − k. A hash map of how many times each running total has appeared answers that in O(1), so the whole count is one O(n) pass. This works with negative numbers, where a sliding window doesn't.

Common mistakes

  • Off-by-one at the left edge: when l = 0 there's nothing to subtract. Many people use a length n + 1 array with prefix[0] = 0 to avoid the special case.
  • Forgetting to seed the map with {0: 1}, which misses subarrays that start at index 0.
  • Using prefix sums on an array that changes often. Use a Fenwick or segment tree instead.
  • Overflow when totals get large in Java; use long.
