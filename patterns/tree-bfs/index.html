Tree BFS

Breadth-first search visits a tree level by level with a queue. Processing one whole level per loop iteration makes level-based questions direct: averages, right side views, zigzags and the minimum depth.

Coding pattern

Picture it. Reading a family tree generation by generation: grandparents first, then all their children, then all the grandchildren, before moving down again.

Recognise it

  • The question mentions levels, rows, depth order, or what's visible from one side.
  • The minimum depth or the nearest leaf: BFS finds it without exploring the whole tree.
  • Connecting nodes on the same level, or serialising a tree row by row.

The template

queue = [root]
while queue not empty:
    size = queue.length                   ← nodes on this level
    for i in 0..size − 1:
        node = dequeue
        process node (i tells you its position in the level)
        enqueue node.left and node.right if present
    finish the level

How it works

The key line is taking size = queue.length before the inner loop. At that moment the queue holds exactly the current level, and the children added during the loop belong to the next one.

With levels separated:

  • Right side view: the last node of each level.
  • Zigzag: reverse every other level (or insert at the front of the level's list on odd levels).
  • Average of levels: sum and divide by size.
  • Minimum depth: the first leaf you meet ends the search.

DFS can answer most of these too, by passing the depth down, but BFS keeps the level order natural and can stop early.

Cost of each operation

OperationTimeWhy
Level-order traversalO(n) timeEach node is enqueued and dequeued once.
Queue sizeO(w) spacew is the widest level; up to n / 2 in a full tree.
Minimum depthO(n) worst caseOften far less: BFS stops at the first leaf.

Code

Every function uses the same "take the level size, then process exactly that many nodes" loop.

Common mistakes

  • Reading queue.length inside the loop condition while the loop is adding children.
  • Using shift() in JavaScript on a big queue (O(n) each). Keep a head index or build the next level in a new array.
  • Enqueuing null children, then dereferencing them.
  • Using DFS for minimum depth and forgetting that a node with one child isn't a leaf.
