Trie

Whenever a problem keeps asking about prefixes of many words, build a trie once and walk it. Every question about a prefix becomes a walk of the prefix's length, no matter how many words there are.

Coding pattern

Picture it. A library catalogue drawer system: one drawer per first letter, one folder per second letter inside it, and so on. Finding every book starting with "mou" means opening three nested drawers, not reading every card.

Recognise it

  • Autocomplete, search suggestions, "words starting with".
  • Replacing words by their shortest root, or checking many words against a dictionary of prefixes.
  • Searching for many words at once in a grid (Word Search II), pruning paths no word starts with.
  • Longest common prefix across a set of strings.

The template

build: insert every word into the trie (mark word ends)
query(prefix):
    node = root
    for each char in prefix:
        node = node.child[char]; if missing: stop early
    use node: is it a word end? which words lie below it?

How it works

The data structure is covered on the Trie page. This pattern is about using it:

  • Replace words: for each word in a sentence, walk the trie and stop at the first node marked as a root. If the walk falls off the trie first, keep the word.
  • Search suggestions: after each typed letter, walk one step further and collect up to three words below the current node, visiting children in alphabetical order.
  • Longest common prefix: insert all words, then walk down from the root while the node has exactly one child and isn't the end of a word.

Cost of each operation

OperationTimeWhy
Build a trie of all wordsO(total characters)One node step per character.
One prefix queryO(prefix length)Plus the size of any output collected below it.
Replace words in a sentenceO(sentence length)Each word walks at most its own length.

Code

Each node keeps 26 child slots, so a depth-first walk visits children in alphabetical order without sorting.

Common mistakes

  • Forgetting the end-of-word flag, so a prefix that isn't a word is treated as one.
  • Collecting suggestions in insertion order instead of alphabetical order.
  • Rebuilding the trie for every query instead of once.
