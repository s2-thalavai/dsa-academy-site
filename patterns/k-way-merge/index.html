K-way merge

To merge k sorted lists, put the first item of each list into a min-heap. Pop the smallest, then push the next item from the same list. The heap never holds more than k items.

Coding pattern

Picture it. Merging the queues at k checkout counters into one line by arrival time. You only need to compare the person at the front of each queue; whoever arrived earliest goes next, and the next person in their queue steps up.

Recognise it

  • Several sorted lists, arrays, files or streams must be combined into one sorted output.
  • The k-th smallest element across sorted rows, a sorted matrix, or pairwise sums.
  • The smallest range that includes at least one element from each list.

The template

heap = [(first value, list index, position 0) for each non-empty list]
while heap not empty:
    value, i, j = pop smallest
    output value
    if list i has an item at j + 1: push (lists[i][j + 1], i, j + 1)

How it works

The next item of the merged output must be the smallest of the current heads, and those heads are exactly what the heap holds. Each item is pushed and popped once at a cost of O(log k), so merging N items in total is O(N log k).

Compare this with merging pairs one after another: merging list 1 with 2, then the result with 3, and so on copies the early items k times, which is O(N × k). Merging pairs in a balanced tournament (1+2, 3+4, …, then the results) gets back to O(N log k) without a heap.

A sorted matrix is k sorted rows, so the k-th smallest element is a k-way merge stopped after k pops.

Cost of each operation

OperationTimeWhy
Merge k lists with N items in totalO(N log k) time, O(k) heapEvery item passes through a heap of size at most k.
K-th smallest in an n × n sorted matrixO(k log n)Stop after k pops.
K smallest pair sumsO(k log k)Push pairs lazily, starting from the smallest.

Code

Arrays stand in for linked lists to keep the demo short; with linked lists the heap holds node references instead of (list, position) pairs.

Common mistakes

  • Pushing every item of every list into the heap at the start (O(N) memory) instead of just the heads.
  • Comparing heap entries that tie on value but then compare node objects (a TypeError in Python). Add the list index as a tie-breaker.
  • Forgetting to skip empty lists.
