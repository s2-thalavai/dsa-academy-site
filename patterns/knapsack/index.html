Knapsack

Knapsack problems choose items under a budget: a capacity, a target sum, an amount of money. The DP is indexed by the budget, and the loop direction decides whether each item can be used once (0/1) or many times (unbounded).

Coding pattern

Picture it. Packing a carry-on bag with a weight limit. For each item you ask: is the best bag of this weight better with this item or without it? Whether you can pack two of the same item changes how you fill the table.

Recognise it

  • Pick a subset of numbers that reaches or doesn't exceed a target.
  • Split numbers into two groups with equal (or closest) sums.
  • Count the ways to make an amount from coins, or assign + and − signs to reach a target.
  • Two budgets at once (a count of zeros and a count of ones) means a 2D budget.

The template

dp[0] = base (true / 1 / 0), dp[other budgets] = neutral
for each item with cost c:
    0/1 (use once):      for b from BUDGET down to c: dp[b] = combine(dp[b], dp[b − c] + item)
    unbounded (reuse):   for b from c up to BUDGET:   dp[b] = combine(dp[b], dp[b − c] + item)

How it works

In the 2D form, dp[i][b] is the best answer using the first i items with budget b: skip item i (dp[i − 1][b]) or take it (dp[i − 1][b − c] + value). Each row reads only the previous row, so one array of budgets is enough, and the direction of the inner loop does the bookkeeping:

  • Downwards (0/1): dp[b − c] hasn't been updated for this item yet, so it still means "without this item". Each item is counted once.
  • Upwards (unbounded): dp[b − c] may already include this item, so it can be taken again.

Many problems need a short translation first. Partition equal subset sum is "can a subset reach total / 2?". Target sum with signs is "count subsets summing to (total + target) / 2". Last stone weight II is "get one group as close to total / 2 as possible".

Loop order also matters for counting. In coin change II, coins in the outer loop count combinations (2 + 1 and 1 + 2 are the same); amounts in the outer loop would count orderings.

Cost of each operation

OperationTimeWhy
0/1 or unbounded knapsackO(n × B) time, O(B) spacen items × B budgets; one budget array.
Subset sum / equal partitionO(n × total)Pseudo-polynomial: fast when the total is small.
Two budgets (ones and zeroes)O(n × B₁ × B₂)A 2D budget table, both loops downwards.

Code

Each solution is a one-dimensional budget array. Watch the loop direction: downwards for use-once, upwards for unlimited reuse.

Common mistakes

  • Looping budgets upwards for 0/1 problems, which reuses items.
  • Swapping the loops in coin change II and counting permutations instead of combinations.
  • Forgetting the parity check: if (total + target) is odd, or the total is odd for an equal partition, the answer is immediately 0 or false.
  • Not seeding dp[0] (one way to make 0; true for reaching 0).
