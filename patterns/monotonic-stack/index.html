Monotonic stack

Keep a stack whose values are always in increasing (or decreasing) order. When a new value breaks the order, every value it pops has just found its next greater (or smaller) element.

Coding pattern

Picture it. People queueing for a view, each one taller than the person in front of them can see past. When a tall person arrives, everyone shorter at the back of the line now has their view blocked by them: that tall person is their "next taller". Those people step out, and the tall person joins the line.

Recognise it

  • For each element, find the next or previous greater or smaller element.
  • "How many days until a warmer day?", stock spans, buildings that can see the ocean.
  • Areas bounded by heights: largest rectangle in a histogram, trapping rain water.
  • A nested loop scans right from each element looking for the first bigger one: O(n²).

The template

stack = empty (holds indices, values kept decreasing)
for i from 0 to n − 1:
    while stack not empty and a[i] > a[stack.top]:
        j = stack.pop()
        answer[j] = i        ← a[i] is the next greater element for j
    stack.push(i)
whatever remains on the stack has no next greater element

How it works

The stack holds elements still waiting for their answer. Because each one is smaller than the one below it, a new element that is bigger than the top answers the top, then possibly the next one down, and so on. It's then pushed to wait for its own answer.

a = [2, 1, 2, 4, 3]
i=0 push 0            stack [2]
i=1 push 1            stack [2, 1]
i=2 2 > 1: ans[1]=2   stack [2] then push → [2, 2]
i=3 4 > 2, 4 > 2: ans[2]=4, ans[0]=4; push → [4]
i=4 push              stack [4, 3]
left over: ans[3] = ans[4] = −1      →  [4, 2, 4, −1, −1]

For largest rectangle, an increasing stack does the same job: when a bar is popped, the current index is the first bar to its right that's shorter, and the new stack top is the first one to its left that's shorter. That gives the widest rectangle using the popped bar's height.

Cost of each operation

OperationTimeWhy
Next greater element for every indexO(n) time, O(n) spaceEach index is pushed once and popped at most once.
Daily temperatures, stock spanO(n)Same push/pop argument.
Largest rectangle in a histogramO(n)Each bar is popped once and its widest rectangle measured then.

Code

Every stack here holds indices. Values are read through the index when needed.

Common mistakes

  • Storing values instead of indices when you need distances or widths.
  • Using >= vs > inconsistently, which changes how equal values are handled.
  • Forgetting the elements left on the stack at the end (they have no next greater element, or need a final flush for histograms).
