Backtracking

Build candidates one choice at a time, check constraints as early as possible, and undo the last choice to try the next one. This page applies the technique to the problem shapes interviews use most.

Coding pattern

Picture it. Filling in a crossword. You pencil in a word, then try the crossing words. When nothing fits, you erase the most recent word and try another, without erasing the parts of the grid that were fine.

Recognise it

  • "All combinations", "all permutations", "all ways to partition", "generate every valid …".
  • Searching a grid for a path that spells a word, or filling a board under rules (Sudoku, N-Queens).
  • Small input limits (n up to about 15–20, or strings up to about 16), which hint that exponential search is expected.

The template

solve(position, path):
    if path is complete: record a copy; return
    for each option at this position:
        if option breaks a rule: skip            ← prune early
        apply option (path.add, mark the cell)
        solve(next position, path)
        undo option (path.remove, unmark)

How it works

The general technique is on the Backtracking technique page. Here are the four problem shapes that come up most, all solved below:

  • Letter combinations: one position per digit, three or four letters per position.
  • Generate parentheses: at each step add ( if any are left, or ) if it wouldn't close more than were opened. The pruning rule is what keeps every result valid.
  • Word search: DFS from each cell, marking the cell as used on the way in and unmarking it on the way out.
  • Palindrome partitioning: choose the end of the first piece, keep it only if it's a palindrome, then partition the rest.

Cost of each operation

OperationTimeWhy
Letter combinations of n digitsO(4ⁿ × n)Up to 4 letters per digit; O(n) to copy each result.
Generate n pairs of parenthesesO(4ⁿ / √n)The n-th Catalan number of results, each of length 2n.
Word search in an R × C gridO(R × C × 3ᴸ)Each step has at most 3 new directions; L is the word length.
Palindrome partitioningO(n × 2ⁿ)Up to 2ⁿ⁻¹ ways to cut, O(n) palindrome check and copy.

Code

Every function keeps one shared path and undoes each change after the recursive call returns.

Common mistakes

  • Forgetting to unmark a grid cell after exploring it, so later paths think it's still in use.
  • Saving the path itself instead of a copy.
  • Checking constraints only at the end instead of while building, which explores far more branches.
  • Off-by-one when slicing substrings for partitions.
