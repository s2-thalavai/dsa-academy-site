Monotonic deque

A deque that keeps its values in sorted order gives the maximum (or minimum) of a sliding window in O(1). Values that can never be the answer again are dropped from the back; values that leave the window are dropped from the front.

Coding pattern

Picture it. A leaderboard for the last k games. When a new player scores higher than people near the bottom, those people can never top the board while the newcomer is still on it, so they're removed. The leader is always at the front, until their game falls out of the window.

Recognise it

  • The maximum or minimum of every window of size k.
  • A sliding window whose rule depends on the window's max and min (absolute difference within a limit).
  • DP where each state takes the best of the previous k states (jump game VI, constrained subsequence sum).
  • Shortest subarray with sum at least k when numbers can be negative (deque over prefix sums).

The template

deque = empty (indices, values decreasing from front to back)
for i from 0 to n − 1:
    while deque not empty and a[deque.back] <= a[i]: pop back   ← can never win again
    push i at the back
    if deque.front <= i − k: pop front                          ← left the window
    if i >= k − 1: window max = a[deque.front]

How it works

A number in the window can only be the maximum while no larger, newer number is in the window too. So when a[i] arrives, every smaller number at the back is useless for the rest of its life and gets popped. What's left is in decreasing order, so the front is always the maximum.

The front also has to leave once it slides out of the window, which is why it's a deque rather than a stack: values leave from both ends.

Each index is pushed once and popped at most once, so all windows together cost O(n), compared with O(n × k) for rescanning each window.

Cost of each operation

OperationTimeWhy
Sliding window maximum or minimumO(n) time, O(k) spaceEach index enters and leaves the deque once.
Longest window with max − min ≤ limitO(n)Two deques (one for max, one for min) plus a variable window.
Shortest subarray with sum ≥ kO(n)A deque of increasing prefix sums.

Code

JavaScript and TypeScript use an array with a head index as the deque, so removing from the front is O(1).

Common mistakes

  • Storing values instead of indices, so you can't tell when the front has left the window.
  • Popping from the front with if before pushing the new index; order matters less than doing both checks every step.
  • Using an array's shift() in JavaScript, which is O(n). Keep a head index.
  • Using < instead of <= when popping, which keeps equal values around unnecessarily (still correct, just slower).
