Topological sort

When tasks depend on other tasks, a topological order lists every task after all of its prerequisites. It exists exactly when the dependency graph has no cycle, so the same algorithm also detects cycles.

Coding pattern

Picture it. Getting dressed: socks before shoes, shirt before jacket. Write each "this before that" as an arrow, then repeatedly put on anything whose prerequisites are already on.

Recognise it

  • Prerequisites, dependencies, build order, "X must happen before Y".
  • Can all tasks be finished? That's the same as asking whether the directed graph has a cycle.
  • Ordering letters from a sorted alien dictionary, or recipes from ingredients.

The template

Kahn's algorithm (BFS):
    indegree[v] = number of edges into v
    queue = every v with indegree 0
    while queue not empty:
        u = dequeue; append u to order
        for each v with u → v:
            indegree[v] −= 1
            if indegree[v] == 0: enqueue v
    if order has all V nodes: it's a valid order, else there's a cycle

How it works

A node with in-degree 0 has nothing left to wait for, so it can go next. Removing it (by decrementing its neighbours) may free up others. If the queue empties before every node is output, the remaining nodes all wait on each other: that's a cycle.

The DFS alternative colours nodes white (unvisited), grey (on the current path) and black (finished). Reaching a grey node means a cycle. Appending nodes as they turn black and then reversing gives a topological order. The same colouring finds eventual safe states: nodes that can't reach a cycle.

Cost of each operation

OperationTimeWhy
Kahn's algorithmO(V + E)Each node is enqueued once and each edge decrements one in-degree once.
DFS with coloursO(V + E)Each node turns grey and black once.

Code

Prerequisites use LeetCode's format: [course, prerequisite] means an edge from the prerequisite to the course.

Common mistakes

  • Getting edge direction backwards. In LeetCode's course schedule, [a, b] means b must come before a, so the edge is b → a.
  • Forgetting to check that every node was output, and returning a partial order when there's a cycle.
  • In the DFS version, treating any visited node as a cycle; only nodes on the current path (grey) are.
