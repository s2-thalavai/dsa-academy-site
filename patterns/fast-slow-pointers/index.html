Fast and slow pointers

Two pointers walk the same sequence at different speeds, usually one step and two steps. If there's a loop, the fast one catches the slow one; if not, the fast one reaching the end means the slow one is at the middle.

Coding pattern

Picture it. Two runners on a track. On a straight road the faster runner just gets further ahead. On a circular track the faster runner eventually comes up behind the slower one and laps them. Meeting proves the track is a loop.

Recognise it

  • Detect a cycle in a linked list or in a sequence defined by next = f(current).
  • Find the middle of a linked list in one pass, or the k-th node from the end.
  • O(1) extra space is required, so a visited set isn't allowed.

The template

slow = head, fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
    if slow == fast: there is a cycle
when fast reaches the end, slow is at the middle

How it works

Inside a cycle, the gap between fast and slow shrinks by one each step, so they must meet within one lap. To find where the cycle starts, move one pointer back to the head and advance both one step at a time; the distances work out so that they meet exactly at the entrance (Floyd's algorithm).

The same idea works on anything with a "next" function: in Happy Number, next(n) is the sum of the squares of n's digits, and in Find the Duplicate Number, next(i) = nums[i].

Cost of each operation

OperationTimeWhy
Cycle detectionO(n) time, O(1) spaceThe fast pointer meets the slow one within one extra lap.
Find the cycle's startO(n)A second phase of at most n steps.
Middle of a listO(n)Fast covers the list in n / 2 steps.

Common mistakes

  • Checking only fast.next (or only fast) before stepping twice, which throws a null error.
  • Comparing values instead of node identity, which reports false cycles when values repeat.
  • Getting the first vs second middle wrong for even-length lists; check what the problem wants.
