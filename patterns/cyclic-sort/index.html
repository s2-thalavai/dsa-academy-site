Cyclic sort

When an array holds numbers from a known range like 1 to n, each value has a home: index value − 1. Swapping every number home in one pass sorts it in O(n) and exposes what's missing or repeated.

Coding pattern

Picture it. Numbered seats in a theatre and guests holding tickets. Each guest who's in the wrong seat swaps with whoever is in their seat. After at most one swap per guest, everyone sits in their own seat, and an empty or double-booked seat stands out at a glance.

Recognise it

  • The values are in a range tied to the array length: 1 to n, 0 to n, or nearly so.
  • The question asks for missing numbers, duplicates, or the smallest missing positive.
  • You must use O(1) extra space (no hash set) and may modify the array.

The template

i = 0
while i < n:
    home = a[i] − 1                          (or a[i] for a 0..n range)
    if a[i] is in range and a[home] != a[i]: swap(a[i], a[home])
    else: i += 1
then scan: any index i with a[i] != i + 1 tells you what's missing or repeated

How it works

The trick is the a[home] != a[i] check: if the home slot already holds the same value, swapping would loop forever, so that value is a duplicate and you move on. Values outside the range (zero, negatives, numbers above n) are left where they are; the final scan treats their slots as empty.

Even though there's a loop inside a loop, every swap puts one number in its final place, so there are at most n swaps plus n increments: O(n).

Cost of each operation

OperationTimeWhy
Cyclic sortO(n) time, O(1) spaceAt most n swaps; each places one number home for good.
Find missing or duplicate numbersO(n)One sorting pass plus one scan.
First missing positiveO(n) time, O(1) spaceIgnore values outside 1..n; the first slot without its own number is the answer.

Code

Each function copies its input first, then swaps numbers home and scans for the slots that don't hold their own value.

Common mistakes

  • Swapping without checking that the home slot doesn't already hold the same value, which loops forever on duplicates.
  • Incrementing i after a swap. The new value at i might also need moving.
  • Off-by-one between 0..n−1 and 1..n ranges.
  • Forgetting to skip out-of-range values before using them as an index.
