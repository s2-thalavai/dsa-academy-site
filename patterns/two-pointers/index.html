Two pointers

Two indices move through the data, toward each other from both ends or in the same direction at different speeds, so one pass replaces a nested loop.

Coding pattern

Picture it. Two people searching a sorted bookshelf for two books whose prices add up to a budget. One starts at the cheap end, one at the expensive end. If the pair costs too much, the person at the expensive end steps in; too little, the cheap end steps in. They never need to recheck a book.

Recognise it

  • The input is sorted, or sorting it first doesn't break the problem.
  • You're looking for a pair (or triple) with a target sum, difference or product.
  • The problem compares the two ends of a sequence: palindromes, reversing, the widest container.
  • You must work in place with O(1) extra space: remove duplicates, move zeroes, partition.

The template

left = 0, right = n − 1
while left < right:
    if condition(a[left], a[right]) is met: record answer; move one or both
    else if we need a bigger value: left += 1
    else:                            right −= 1

How it works

Brute force checks every pair, which is O(n²). Two pointers use order to throw away candidates: on sorted data, if a[left] + a[right] is too small, then a[left] paired with anything to its right is too small too, so left can move on for good. Each step discards one element, so the whole scan is O(n).

There are two flavours:

  • Opposite ends (converging): pair sums, palindromes, container with most water, three-sum after fixing one number.
  • Same direction (reader and writer): one pointer reads every element, the other marks where the next kept element goes. Remove duplicates and move zeroes work this way.

Common mistakes

  • Using converging pointers on unsorted data, where moving one pointer doesn't rule anything out.
  • Loop condition left <= right when the two pointers must be different elements.
  • In three-sum, not skipping duplicate values, so the same triple is reported several times.
  • Moving the wrong pointer: in container with most water, always move the shorter side.
