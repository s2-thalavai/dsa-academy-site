Modified binary search

Binary search works whenever you can look at a middle element and decide which half can't contain the answer. That's true far beyond plain sorted arrays: rotated arrays, peaks, boundaries and answer ranges.

Coding pattern

Picture it. Finding the page where a misfiled chapter starts in a book whose second half was bound before the first. Open the middle: by comparing the page number with the first and last pages, you can still tell which half is in order, and whether your page is inside it.

Recognise it

  • The input is sorted, partly sorted (rotated), or has a monotonic yes/no property.
  • The question asks for a first or last position, a boundary, a peak, or a minimum.
  • An O(log n) solution is expected, or n is up to 10⁹ (searching values, not indices).

The template

lo, hi = search range
while lo < hi (or lo <= hi):
    mid = lo + (hi − lo) / 2
    decide which half must contain the answer
    keep that half: lo = mid + 1 or hi = mid (or mid − 1)

How it works

The only question that matters at each step is: which half can I throw away?

  • Rotated sorted array: one half of [lo, mid] and [mid, hi] is always in order. If the target lies within the in-order half's range, search there; otherwise search the other half.
  • Minimum of a rotated array: if a[mid] > a[hi], the drop (and the minimum) is to the right; otherwise it's at mid or to the left.
  • Peak element: if a[mid] < a[mid + 1], you're on an uphill slope, so a peak lies to the right. Otherwise there's one at mid or to the left.
  • First and last position: run a lower-bound search for the first >= target and another for the first > target.

Write down the loop invariant ("the answer is always in [lo, hi]") and check that every update keeps it. That's what prevents off-by-one bugs.

Cost of each operation

OperationTimeWhy
Search a rotated sorted arrayO(log n)One half is discarded per step.
Minimum of a rotated array, peak elementO(log n)Same halving argument.
First and last positionO(log n)Two lower-bound searches.
Integer square rootO(log x)Binary search over candidate answers 0..x.

Code

Each loop keeps the invariant "the answer is in [lo, hi]" and stops when the range has one candidate.

Common mistakes

  • Mixing lo <= hi with hi = mid, which can loop forever.
  • In rotated search, using strict < where <= is needed when lo == mid.
  • Overflow from mid * mid in square-root search; use long or compare mid <= x / mid.
  • Rotated arrays with duplicates break the "one half is sorted" test; you may have to shrink both ends by one.
