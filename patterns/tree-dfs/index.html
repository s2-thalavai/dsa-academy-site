Tree DFS

Depth-first search on a tree solves a problem for each subtree and combines the answers. Pass information down (like a remaining target) as arguments, and pass results up (like a height) as return values.

Coding pattern

Picture it. Asking an org chart a question. The CEO asks each direct report, who asks their reports, down to people with no reports. Answers flow back up and each manager combines their team's answers before passing them on.

Recognise it

  • A binary tree question about paths, depths, heights, sums or subtree properties.
  • Validating a BST, finding a lowest common ancestor, comparing two trees.
  • The answer for a node depends on the answers for its children (post-order), or on information from its ancestors (pre-order).

The template

dfs(node, info from above):
    if node is null: return base value
    left  = dfs(node.left,  updated info)
    right = dfs(node.right, updated info)
    combine left, right and node.val; maybe update a global best
    return the value the parent needs

How it works

Decide two things before writing any code:

  1. What flows down? A running sum, a remaining target, the allowed (low, high) range for a BST check, the current depth.
  2. What flows up? The subtree's height, whether it's balanced, the best path that ends at this node.

Some problems need both: diameter returns each subtree's height up, but records the best left + right seen at any node in a separate variable. The lowest common ancestor returns the node itself when it's one of the two targets; a node whose left and right calls both return something is the answer.

Cost of each operation

OperationTimeWhy
Any single traversalO(n) timeEach node is visited once.
Recursion stackO(h) spaceh is the height: O(log n) if balanced, O(n) if skewed.
Validate a BSTO(n)Pass down the (low, high) bounds.
Lowest common ancestorO(n)One post-order traversal.

Code

Trees are built from LeetCode's level-order format, where null marks a missing child.

Common mistakes

  • Checking only the immediate children when validating a BST instead of passing bounds down.
  • Returning the wrong thing in diameter: return the height, track the diameter separately.
  • Treating a node with one child as a leaf in path-sum problems; a leaf has no children at all.
  • Using int bounds for BST validation when node values can equal Integer.MIN_VALUE or MAX_VALUE; use long or nullable bounds.
