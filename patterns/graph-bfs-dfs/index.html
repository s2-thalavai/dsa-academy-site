Graph BFS and DFS

Explore a graph (or a grid, or a space of states) from one or more starting points. BFS spreads out in rings and finds the fewest steps; DFS goes deep first and is ideal for reachability, components and flood fill.

Coding pattern

Picture it. Ink dropped on paper spreads in rings: that's BFS, reaching everything one step away before anything two steps away. A person exploring a cave follows one tunnel to its end before backing up to try the next: that's DFS.

Recognise it

  • Islands, regions, provinces, connected cells, flood fill.
  • The fewest moves or minimum time in an unweighted setting: BFS.
  • Spreading from several sources at once (rotting oranges, walls and gates): multi-source BFS.
  • Transforming one state into another one small change at a time (word ladder, lock combinations): BFS over implicit states.

The template

BFS:
    queue = all start nodes; mark them visited
    steps = 0
    while queue not empty:
        repeat queue.size times:
            node = dequeue
            for each neighbour not visited: mark visited; enqueue
        steps += 1

DFS (on a grid):
    dfs(r, c):
        if out of bounds or not wanted or visited: return
        mark visited
        dfs on the 4 neighbours

How it works

Both visit every reachable node once, so both are O(V + E). Choose by what you need:

  • BFS when distance matters. Processing the queue one level at a time gives the number of steps directly. Seeding the queue with every source at once computes the distance to the nearest source for all cells in one pass.
  • DFS when you just need to touch everything connected: counting islands, colouring a region, checking whether a path exists.

The graph is often implicit. In word ladder, the nodes are words and two words are neighbours if they differ in one letter. You never build the graph: you generate neighbours on demand and check them against a set.

Cost of each operation

OperationTimeWhy
BFS or DFS over a graphO(V + E)Every node and edge is handled once.
Over an R × C gridO(R × C)Each cell has at most 4 neighbours.
Word ladderO(N × L × 26)N words, L letters each, 26 replacements per letter, with O(1) set lookups (plus O(L) to build each string).

Code

Flood fill uses an explicit stack so it can't overflow the call stack on large images.

Common mistakes

  • Marking cells visited when they're dequeued rather than enqueued, so they're queued many times.
  • Running a separate BFS from every source instead of one multi-source BFS.
  • Recursion depth: a DFS over a 1000 × 1000 grid can recurse a million times. Use an explicit stack in Java and Python.
  • Counting steps off by one: decide whether the start counts as step 0 or 1 (word ladder counts words, so it starts at 1).
