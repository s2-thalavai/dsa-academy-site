Top K elements

To find the k largest (or smallest, or most frequent) items, keep a heap of size k. Each new item either beats the weakest of the current top k and replaces it, or is ignored.

Coding pattern

Picture it. Choosing a team of 5 from 200 tryouts. You don't rank all 200. You keep 5 names on a whiteboard with the weakest at the top; each new player who beats that weakest name replaces it.

Recognise it

  • The words k largest, k smallest, k most frequent, k closest, k-th largest.
  • Sorting everything would work but is more than you need.
  • Data arrives as a stream and you need the current top k at any time.

The template

heap = min-heap ordered by "how good"         (for the k LARGEST)
for each item:
    push item
    if heap.size > k: pop                      ← drop the weakest
heap holds the top k; heap.top is the k-th largest

How it works

It feels backwards, but to keep the largest k you use a min-heap. The root is the weakest of the current top k, so it's the one to compare against and evict. A heap of size k means each push or pop costs O(log k) rather than O(log n).

For "most frequent", count with a hash map first, then run the same loop over the (value, count) pairs ordered by count. For "closest points", order by squared distance (no square root needed).

When you need only the k-th element once, quickselect finds it in O(n) on average, and bucket sort by frequency works when counts are bounded by n.

Cost of each operation

OperationTimeWhy
Top k with a size-k heapO(n log k) time, O(k) spacen pushes, each O(log k).
Sort everything insteadO(n log n)Fine for small n; wasteful when k ≪ n.
Quickselect for the k-th elementO(n) average, O(n²) worstPartition like quicksort, recurse into one side only.
Top k frequent with bucketsO(n)Bucket i holds values that appear i times.

Code

All three keep a heap of at most k items. JavaScript and TypeScript include a small heap class, since neither has one built in. Results are sorted before printing, because heap order isn't sorted order.

Common mistakes

  • Using a max-heap of everything and popping k times: correct but O(n + k log n) memory and time, and misses the point in streams.
  • Forgetting to pop when the heap grows past k.
  • Comparing with subtraction in Java when values can overflow.
  • Returning the heap's internal order as if it were sorted.
