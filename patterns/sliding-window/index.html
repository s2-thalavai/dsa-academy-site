Sliding window

A window is a contiguous range of the array or string. Instead of recomputing each range from scratch, slide the window: add what enters on the right, remove what leaves on the left.

Coding pattern

Picture it. Watching a train pass through a window. You don't count every carriage on the train each time it moves; you note the carriage that just appeared and forget the one that just left.

Recognise it

  • The question is about a contiguous subarray or substring.
  • It asks for the longest, shortest, or best window, or the number of windows, meeting a condition.
  • A brute force would recompute a sum, count or set for every start and end: O(n²) or worse.
  • The condition can be updated incrementally when one element enters or leaves.

The template

Fixed size k:
    window = first k items
    for end from k to n − 1:
        add a[end]; remove a[end − k]; update the answer

Variable size:
    start = 0
    for end from 0 to n − 1:
        add a[end] to the window
        while the window breaks the rule:
            remove a[start]; start += 1
        update the answer with the window [start, end]

How it works

A fixed-size window keeps its length: every step adds one element and drops one, so a window sum or count changes in O(1).

A variable-size window grows from the right until it breaks a rule (too many distinct characters, sum too large), then shrinks from the left until it's valid again. Each element enters once and leaves once, so the two nested loops are still O(n) in total, not O(n²).

The window's contents are usually summarised by a running sum, a count map or a set, so checking the rule is O(1).

Common mistakes

  • Using a sliding window on problems with negative numbers when the rule assumes sums only grow (minimum size subarray sum).
  • Shrinking with if instead of while, so the window can stay invalid.
  • Updating the answer before the window has reached size k (fixed windows) or while it's still invalid (variable windows).
  • Forgetting to remove a character's count from the map when it drops to zero, so distinct-count checks are wrong.
