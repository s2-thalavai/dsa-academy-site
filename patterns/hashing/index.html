Hashing

Store what you've already seen in a hash map or set, and each new element can ask an O(1) question about everything before it: have I seen my complement, my duplicate, my anagram group?

Coding pattern

Picture it. A guest list at the door. Rather than scanning the whole list for each arriving guest, the host has it alphabetised in a binder with tabs and flips straight to the right page. The binder costs paper, but every check is instant.

Recognise it

  • A nested loop compares every pair, and the inner loop is only looking something up.
  • The problem talks about duplicates, frequencies, complements, groups or "first unique".
  • Order doesn't matter, but membership does.
  • You can trade O(n) extra memory for a faster time.

The template

seen = empty map
for each item x (with index i):
    if the thing x needs is in seen: answer found
    record x in seen (value: index, count or list)

How it works

The pattern replaces "search the past" with "look the past up". For two sum, each number asks whether target − x appeared earlier: one map lookup instead of a scan. For grouping, compute a canonical key (sorted letters for anagrams, a tuple of counts, a normalised shape) and collect items under it.

Choosing the key is most of the work. It must be identical for items that belong together and different otherwise. Sorting a word costs O(L log L); a 26-letter count signature costs O(L).

Cost of each operation

OperationTimeWhy
Membership test or insertO(1) averageHash, go to the bucket, compare a few keys.
Two sum, contains duplicateO(n) time, O(n) spaceOne pass, one lookup per element.
Group anagramsO(n × L log L)Sorting each word's letters builds its key; counting letters makes it O(n × L).
Longest consecutive sequenceO(n)Start counting only at numbers whose predecessor is missing, so each number is visited at most twice.

Code

Java uses LinkedHashMap for the anagram groups so they print in first-seen order, matching JavaScript's Map and Python's dict.

Common mistakes

  • Adding the current element to the map before checking for its complement, so it pairs with itself.
  • Using a key that isn't canonical, so equivalent items land in different groups.
  • Using a mutable list as a key (not allowed in Python; compares by reference in JavaScript).
  • Relying on hash map iteration order for output.
