2D dynamic programming

Two-dimensional DP keeps a table indexed by two things: a row and a column of a grid, or a prefix of one string and a prefix of another. Each cell is built from its neighbours above, to the left, or on the diagonal.

Coding pattern

Picture it. Planning a walk across a city laid out in blocks, only going east or south. The cheapest way to reach a corner is its own toll plus the cheaper way to reach the corner just north or just west of it.

Recognise it

  • A grid where you move right or down and count paths or minimise cost.
  • Two strings compared character by character: subsequences, edits, interleaving.
  • Squares, rectangles or palindromes whose answer at (i, j) extends one at (i − 1, j − 1).

The template

dp = (rows + 1) × (cols + 1) table with base row and column
for i in 1..rows:
    for j in 1..cols:
        dp[i][j] = f(dp[i − 1][j], dp[i][j − 1], dp[i − 1][j − 1], input[i][j])
answer = dp[rows][cols]   (or the best cell seen)
space: keep one row (or two) if each row only reads the previous one

How it works

The base cases are the first row and column: in a grid you can only reach them one way. An extra row and column of zeros (or of empty-prefix values for string problems) keeps the loops free of special cases.

  • Unique paths: dp[i][j] = dp[i − 1][j] + dp[i][j − 1].
  • Longest palindromic subsequence: compare the string with its reverse using the LCS recurrence, or fill dp[i][j] over substrings directly.
  • Maximal square: the largest square ending at a 1 is one more than the smallest of the squares ending above, left and diagonally up-left.

Because each row only reads the row above, most of these need just one array of length cols + 1.

Cost of each operation

OperationTimeWhy
Grid paths and costsO(R × C) time, O(C) spaceOne cell each; keep a single row.
Two-string DP (LCS, edit distance)O(n × m)One cell per pair of prefixes.
Maximal squareO(R × C)One pass with the min-of-three rule.

Code

Unique paths and minimum path sum use a single rolling row; the others keep the full table for clarity.

Common mistakes

  • Off-by-one between dp indices (1-based with the padding row) and input indices (0-based).
  • Initialising the first row and column wrongly, such as with 0 instead of running sums in minimum path sum.
  • When rolling to one row, reading a cell already overwritten in this row when you needed last row's value (save the diagonal first).
