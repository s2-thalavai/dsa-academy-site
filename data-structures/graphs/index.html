Graphs

A graph is a set of nodes (vertices) joined by edges. Roads between cities, friendships, web links, task dependencies and grids are all graphs.

Data structure 15 minute read

Picture it. A city map. Intersections are nodes and streets are edges. One-way streets make it directed; distances or travel times make it weighted. Asking "can I get from here to there, and how fast?" is a graph question.

Kinds of graph

  • Undirected: edges go both ways (friendship). Directed: edges have a direction (follows, one-way streets, "A must happen before B").
  • Weighted: each edge carries a number such as a distance or cost. Unweighted: every edge counts the same.
  • Cyclic or acyclic: whether you can leave a node and come back to it. A DAG (directed acyclic graph) models dependencies, and it's exactly the kind of graph that has a topological order.
  • Connected: every node can reach every other. Otherwise the graph splits into connected components.
  • Dense graphs have edges between most pairs (E close to V²); sparse graphs have far fewer (E close to V). Most real graphs are sparse.

How it sits in memory

Use an adjacency list by default. It uses memory proportional to the edges that exist, and BFS, DFS and Dijkstra all spend their time listing neighbours, which a list does directly.

Use an adjacency matrix when the graph is small and dense, or when you check "is there an edge between u and v?" constantly (Floyd–Warshall works on a matrix).

An edge list (just an array of (u, v, w) triples) is the third common form. Kruskal's algorithm and Bellman-Ford iterate over it directly.

Grids are implicit graphs

You don't need to build anything for a grid. Compute neighbours on the fly with a direction array such as [(-1, 0), (1, 0), (0, -1), (0, 1)], and use the grid itself (or a visited grid) to track what you've seen. A grid with R rows and C columns has V = R × C nodes and at most 4V edges, so BFS or DFS over it is O(R × C).

DAGs

A directed acyclic graph has no cycles, so its nodes can be lined up so that every edge points forward. That line-up is a topological order. Build systems, course prerequisites and spreadsheet recalculation all rely on it. See Topological sort for the algorithm.

Cost of each operation

OperationTimeWhy
Store the graph: adjacency listO(V + E) spaceOne entry per node plus one per edge (two for undirected).
Store the graph: adjacency matrixO(V²) spaceA cell for every pair of nodes, edge or not.
Is there an edge u–v?O(1) matrix, O(deg u) listThe matrix indexes directly; the list scans u's neighbours (O(1) if each list is a hash set).
List the neighbours of uO(deg u) list, O(V) matrixThe matrix has to scan the whole row.
BFS or DFS over everythingO(V + E) with a listEach node is visited once and each edge examined once (twice if undirected). O(V²) with a matrix.

When to use it

Reach for it when

  • The problem talks about connections: friends, routes, prerequisites, dependencies, networks.
  • You're asked about reachability, shortest paths, cycles, ordering or connected groups.
  • There's a grid and you move between neighbouring cells (islands, mazes, flood fill).
  • States connect to other states by moves: word ladders, puzzle solvers, lock combinations.

Think twice when

  • The structure is strictly hierarchical with one parent per node. A tree is simpler.
  • You'd build a dense matrix for a huge sparse graph: 10⁵ nodes means 10¹⁰ cells.

In your language

Notes for Java

  • Adjacency list: List<List<Integer>> adj = new ArrayList<>(); with adj.add(new ArrayList<>()) per node. For weighted edges store int[] {to, weight}.
  • For node labels that aren't 0..n − 1, use Map<String, List<String>> and computeIfAbsent(u, k -> new ArrayList<>()).
  • BFS with ArrayDeque; mark visited in a boolean[] when you enqueue.

Notes for JavaScript

  • const adj = Array.from({ length: n }, () => []); then adj[u].push(v). Don't use new Array(n).fill([]), which shares one array between all nodes.
  • For string labels use Map<string, string[]>.
  • For BFS keep a head index into an array instead of calling shift().

Notes for TypeScript

  • Type it as number[][] or Map<string, string[]>. For weighted graphs, Array<Array<[to: number, w: number]>> names the tuple fields.

Notes for Python

  • adj = defaultdict(list) then adj[u].append(v) handles any hashable label.
  • BFS uses collections.deque. Mark visited in a set (or a list of bools for 0..n − 1 labels).
  • Recursive DFS hits the 1,000-frame recursion limit on long paths; use an explicit stack for big graphs.

Common mistakes

  • Forgetting to add both directions for an undirected edge.
  • Not tracking visited nodes, so cycles cause infinite loops.
  • Marking visited when you pop instead of when you push in BFS, so nodes are queued many times.
  • Assuming the graph is connected. Loop over every node and start a new search from each unvisited one.
  • In grids, swapping rows and columns or forgetting the bounds check.
