Linked lists

A linked list is a chain of nodes. Each node holds a value and a pointer to the next node, so the chain can grow and shrink without ever copying the rest.

Data structure 12 minute read

Picture it. A treasure hunt. Each clue tells you where the next clue is hidden. Adding a clue in the middle is easy: rewrite one clue to point to the new one. But to reach clue 50 you have to follow the first 49.

What a linked list is

A linked list stores values in nodes. A node holds a value and a reference (pointer) to the next node. The list itself only needs to remember the first node, called the head. The last node's next is null.

There are three common shapes:

  • Singly linked: each node points to the next one.
  • Doubly linked: each node also points to the previous one, so you can walk backwards and delete a node you hold in O(1).
  • Circular: the last node points back to the first instead of null. Useful for round-robin scheduling and ring buffers.

How it sits in memory

Nodes are allocated one at a time, wherever the memory allocator finds room. That's the trade-off at the heart of linked lists:

  • Good: inserting or removing a node only rewires pointers. Nothing shifts, so it's O(1) once you're at the right spot.
  • Bad: there's no formula for "the address of node k". To reach it you follow k pointers. And because nodes are scattered, each hop is likely a cache miss, which makes lists slower than arrays to scan.

Dummy nodes and doubly linked lists

A dummy (or sentinel) node sits before the real head and holds no data. Every real node then has a predecessor, so "insert at the front" and "delete the first node" become the same code as anywhere else. Return dummy.next as the new head when you're done.

Reversing a list, step by step

Reversal is the most common linked list operation in interviews. Walk the list with three pointers: prev (the reversed part), curr (the node being moved) and next (saved so you don't lose the rest).

start:   null   1 → 2 → 3 → null
         prev  curr
step 1:  null ← 1    2 → 3 → null      save next = 2, point 1 at prev, advance
                prev curr
step 2:  null ← 1 ← 2    3 → null
                    prev curr
step 3:  null ← 1 ← 2 ← 3              curr is null: prev is the new head
                        prev

Each node is visited once and only three pointers are stored, so reversal is O(n) time and O(1) space.

When to use it

Reach for it when

  • You insert or remove at the front, or next to a node you already hold, many times.
  • You need a building block for an LRU cache (hash map + doubly linked list) or a queue.
  • Interviewers ask: reversal, cycle detection, merging sorted lists and finding the middle are all classic list problems.

Think twice when

  • You need random access by index. Use an array.
  • You iterate over large data and care about speed. Scattered nodes are cache-unfriendly, so arrays usually win even for some insert-heavy work.

In your language

Notes for Java

  • java.util.LinkedList is doubly linked and implements both List and Deque. get(i) is O(n), so don't loop with an index over it.
  • In interviews you'll write your own ListNode { int val; ListNode next; }.
  • Use ListIterator to insert or remove while walking a LinkedList in O(1) per change.

Notes for JavaScript

  • There's no built-in linked list. Use a plain class with val and next; null marks the end.
  • Arrays are usually faster in JavaScript even for queues of modest size, but shift() is O(n), so a linked list or a head index helps for big queues.

Notes for TypeScript

  • Type the node as class ListNode { val: number; next: ListNode | null = null; }. The | null forces you to handle the end of the list.
  • With strictNullChecks, the compiler catches the classic "forgot to check next before using it" bug.

Notes for Python

  • There's no built-in singly linked list. collections.deque is a doubly linked list of blocks with O(1) operations at both ends.
  • A minimal node: class ListNode: __slots__ = ("val", "next"). __slots__ saves memory per node.
  • None marks the end; check while node: rather than while node is not None only if values can't be falsy nodes (nodes are always truthy, so both work).

Code

Insert at the front and the back, delete by value and reverse in place. The dummy head node means none of these needs a special case for an empty list.

Common mistakes

  • Losing the rest of the list: when rewiring, save node.next before you overwrite it.
  • Forgetting the empty-list and single-node cases. A dummy head node removes most of them.
  • Not updating the tail pointer when you delete the last node.
  • Dereferencing null at the end. Check node != null (and node.next != null when you look two ahead).
  • Creating a cycle by accident when reversing or merging, which turns a later loop infinite.
