Arrays

An array is a row of equal-sized boxes in one unbroken block of memory. Knowing the address of the first box tells you the address of every other box.

Data structure 15 minute read

Picture it. A row of numbered lockers in a corridor. If you know where locker 0 is and every locker is the same width, you can walk straight to locker 37 without opening the 37 before it. Adding a new locker in the middle, though, means shifting every locker after it one place along.

What an array is

An array stores a fixed number of values of the same type, one after another, in a single block of memory. Each value sits in a cell, and each cell is identified by its index: 0 for the first, 1 for the second, up to n − 1.

Because the cells are the same size and touch each other, the computer can find any cell with one calculation. That is the array's superpower, and almost everything else about arrays follows from it.

How it sits in memory

To read a[3], the machine computes base + 3 × 4 and loads from that address. It never looks at a[0], a[1] or a[2]. This takes the same time for index 3 as for index 3 million, so reading or writing by index is O(1).

The same layout makes arrays fast in practice, not just in theory. CPUs load memory in chunks called cache lines (typically 64 bytes). Reading a[0] brings a[1] to a[15] along with it, so a loop over an array mostly reads from the cache.

Two-dimensional arrays

A grid with rows and columns is how you think about a 2D array. Memory is still a single line of addresses, so the grid has to be laid out flat.

There are two ways to flatten a grid:

  • Row-major puts each row one after another. The address of grid[i][j] is base + (i × cols + j) × size. Java, C, C++ and NumPy (by default) use it.
  • Column-major puts each column one after another. The address is base + (j × rows + i) × size. Fortran, MATLAB and R use it.

The order matters for speed. In a row-major language, looping over j in the inner loop walks memory in order and stays in the cache. Swapping the loops jumps cols × size bytes every step, which can be several times slower on large grids.

Higher dimensions extend the same idea: for a[i][j][k] with shape (X, Y, Z), the row-major offset is (i × Y + j) × Z + k.

One Java caveat: int[][] is really an array of arrays. Each row is its own block, and the outer array holds references to them. That is why rows can have different lengths, and why the address formula describes a true 2D block (as in C or NumPy) rather than Java's layout.

Static and dynamic arrays

A static array has a size fixed when it is created. Java's int[] and C's arrays are static.

A dynamic array (Java's ArrayList, Python's list, JavaScript's Array) looks like it can grow forever. Underneath it is a static array with some spare room, called the capacity. When an append finds no room left, it allocates a bigger block and copies every element across.

Why appends are still O(1)

A single resize costs O(n), because it copies n elements. But if the capacity doubles each time, resizes get rarer as the array grows. After n appends the copies total at most 1 + 2 + 4 + … + n/2, which is less than n. Add the n ordinary writes and the total work is under 2n, or O(1) per append on average. That is what amortised O(1) means: some appends are expensive, but the average over any long run is constant.

Growing by a fixed amount instead (say 10 slots at a time) breaks this. The copies become 10 + 20 + 30 + …, which is O(n²) in total.

Strings are character arrays

A string is an array of characters. In Java, JavaScript and Python, strings are also immutable: you can't change a character in place. Every "change" builds a new string.

That makes s += c inside a loop a hidden O(n²) trap, because each += copies the whole string so far. Collect pieces in a dynamic array or a builder, then join them once.

Slow:  for each word: result = result + word        → copies 1 + 2 + … + n characters
Fast:  for each word: parts.append(word); join once → copies each character once

When you need to edit characters (reversing in place, swapping, sorting letters), convert to a character array first: s.toCharArray() in Java, list(s) in Python, [...s] in JavaScript.

When to use it

Reach for it when

  • You read by position far more often than you insert in the middle.
  • You iterate in order. Contiguous memory is cache-friendly, so loops over arrays are fast in practice.
  • The size is known, or grows mostly at the end.
  • You need the building block for something else: heaps, hash tables, stacks and matrices are all arrays underneath.

Think twice when

  • You insert or delete near the front often. Use a deque or a linked list.
  • You look up by key rather than position. Use a hash map.
  • You need the smallest item repeatedly. Use a heap.

In your language

Notes for Java

  • int[] is a fixed-size array of primitives, stored contiguously. Its length is fixed at creation: new int[n].
  • ArrayList<Integer> is a dynamic array. It grows by about 1.5× when full, and stores references to boxed Integer objects, so it uses more memory and is slower to scan than int[].
  • int[][] is an array of arrays: each row is a separate block, so rows can have different lengths (jagged) and are not guaranteed to sit next to each other.
  • String is immutable. Building a string with += in a loop copies every time (O(n²)); use StringBuilder.

Notes for JavaScript

  • Array is dynamic and can hold mixed types. Engines store dense arrays of small integers or doubles contiguously, but holes (a[1000] = 1 on an empty array) or mixed types make them slower.
  • For real fixed-size numeric arrays, use typed arrays: new Int32Array(n) is one contiguous block of 32-bit integers.
  • push/pop are O(1); shift/unshift are O(n) because every element moves.
  • Strings are immutable; str[i] reads a UTF-16 code unit. Build long strings with an array and join("").

Notes for TypeScript

  • Same runtime as JavaScript. number[] and Array<number> are dynamic arrays; Int32Array is fixed-size and contiguous.
  • readonly number[] stops you mutating an array you were only meant to read, which catches a common class of bugs in helper functions.
  • Tuples like [number, number] type a fixed-length array, handy for pairs and coordinates.

Notes for Python

  • list is a dynamic array of references to objects. It over-allocates when it grows, so append is amortised O(1).
  • insert(0, x) and pop(0) are O(n). For a queue use collections.deque.
  • [[0] * cols] * rows creates rows references to the same inner list. Use [[0] * cols for _ in range(rows)].
  • str is immutable. Join pieces with "".join(parts) instead of += in a loop.
  • For contiguous numeric data, array.array("i") or NumPy arrays store raw values, not references.

Common mistakes

  • Off-by-one on bounds: valid indices are 0 to n − 1. Loops written i <= n read past the end.
  • Modifying an array while iterating over it with a for-each loop. Iterate over indices, or build a new array.
  • Assuming insert or remove in the middle is cheap. It is O(n) because everything after it shifts.
  • Sharing rows by accident when building a 2D array in Python, so setting one cell changes a whole column.
  • Comparing arrays with ==. In Java and JavaScript that compares references; use Arrays.equals or compare element by element.
  • Concatenating strings in a loop, which is O(n²) because strings are immutable.
