Trees

A tree is a hierarchy: one root node, and every other node has exactly one parent. Binary trees give each node at most two children, and binary search trees keep them in sorted order.

Data structure 16 minute read

Picture it. A company org chart. The CEO is the root, each manager has a few direct reports, and people with no reports are the leaves. Finding someone by walking down from the top takes as many steps as there are levels, not as many as there are employees.

Vocabulary

  • Root: the top node, with no parent.
  • Parent, child, sibling: the usual family relationships.
  • Leaf: a node with no children.
  • Depth of a node: edges from the root to it. Height of a tree: the largest depth (some books count nodes instead of edges, so check which one a problem means).
  • Subtree: a node and everything below it. Every subtree is itself a tree, which is why recursion fits trees so well.

Binary trees and binary search trees

A binary tree gives every node at most two children, left and right. A binary search tree (BST) adds an ordering rule: for every node, all keys in its left subtree are smaller and all keys in its right subtree are larger.

The rule turns search into a walk: compare with the current node, then go left or right. Each step drops a whole subtree, so a tree with height h needs at most h + 1 comparisons.

How it sits in memory

A tree can also live in an array when it's complete (every level full except possibly the last, filled left to right). Then the children of index i are at 2i + 1 and 2i + 2, with no pointers at all. Heaps use exactly this layout.

Traversals

There are four standard orders. The three depth-first ones differ only in when you visit the node relative to its subtrees.

Order Visit On the tree above Typical use

In-order left, node, right 1 3 4 6 7 8 10 13 14 A BST comes out sorted
Post-order left, right, node 1 4 7 6 3 13 14 10 8 Delete or size subtrees, evaluate expressions
Level order level by level 8 · 3 10 · 1 6 14 · 4 7 13 Shortest depth, views by level

The depth-first orders use recursion (or an explicit stack). Level order uses a queue: that's breadth-first search on a tree.

Balanced trees

Insert 1, 2, 3, 4, 5 into a plain BST and you get a chain: every node has only a right child, and operations are O(n). Self-balancing trees fix this by restructuring with rotations after inserts and deletes.

  • AVL trees keep the heights of every node's two subtrees within 1 of each other. They're strictly balanced, so lookups are slightly faster.
  • Red-black trees colour nodes red or black and enforce rules that keep the longest path at most twice the shortest. They do fewer rotations on updates, which is why Java's TreeMap and C++'s std::map use them.

You rarely implement either in an interview. Know that they exist, that they guarantee O(log n), and how a rotation works at a high level.

N-ary trees

Nodes can have any number of children, stored as a list: children: List<Node>. File systems and the HTML DOM are N-ary trees. Traversals work the same way; just loop over the children instead of visiting left and right.

Advanced: segment trees and Fenwick trees

Both answer range queries on an array (sum, minimum, maximum of a[l..r]) while still allowing updates, each in O(log n).

  • A segment tree stores, for each node, the answer for a range of the array. The root covers everything; each child covers half its parent's range. A query combines O(log n) nodes. It supports any associative operation, including min and max, and with lazy propagation even range updates.
  • A Fenwick tree (binary indexed tree) stores partial sums in a plain array of size n + 1. Index i covers the range ending at i whose length is the lowest set bit of i (i & -i). It's shorter to write but naturally handles only sums and other invertible operations.

When to use it

Reach for it when

  • Data is naturally hierarchical: file systems, the DOM, org charts, expression parse trees.
  • You need keys in sorted order with fast insert and delete: a balanced BST (TreeMap).
  • You need the nearest key above or below a value (floor and ceiling queries).
  • You need fast range sums or minimums with updates: segment or Fenwick trees.

Think twice when

  • You only need exact-key lookup. A hash map is simpler and faster on average.
  • You need the min or max repeatedly but not sorted order. A heap is lighter.

In your language

Notes for Java

  • TreeMap<K, V> and TreeSet<E> are red-black trees: O(log n) insert, delete and search, plus floorKey, ceilingKey, headMap and tailMap.
  • Interview trees use class TreeNode { int val; TreeNode left, right; }.
  • Deep recursion on a skewed tree of 10⁵ nodes can throw StackOverflowError; use an explicit stack for safety.

Notes for JavaScript

  • There's no built-in balanced BST. Write class TreeNode { constructor(val) { this.val = val; this.left = this.right = null; } }.
  • For ordered keys in practice, keep a sorted array and binary search when updates are rare.

Notes for TypeScript

  • Type children as TreeNode | null. Optional chaining (node?.left) shortens null checks in traversals.

Notes for Python

  • There's no built-in BST. The sortedcontainers package (SortedList, SortedDict) is the usual substitute, and it's available on many platforms but not all online judges.
  • bisect on a sorted list gives floor and ceiling lookups in O(log n), with O(n) inserts.
  • The default recursion limit is 1,000, so recursive DFS on deep trees may need sys.setrecursionlimit or an explicit stack.

Common mistakes

  • Checking the BST property only against the parent. Every node must be within the bounds set by all its ancestors.
  • Forgetting the null child base case in recursion.
  • Confusing height and depth, or counting edges in one place and nodes in another.
  • Assuming a BST is balanced. Sorted inserts make it a linked list with O(n) operations.
  • Using recursion on very deep trees and overflowing the stack.
