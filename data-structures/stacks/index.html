Stacks

A stack keeps items in a pile. You can only add to the top or take from the top, so the last item in is the first one out (LIFO).

Data structure 10 minute read

Picture it. A stack of plates. You put clean plates on top, and you take plates from the top. Getting the bottom plate means lifting off every plate above it first.

What a stack is

A stack supports three operations:

  • push(x) puts x on top.
  • pop() removes and returns the top item.
  • peek() returns the top item without removing it.

Nothing else is allowed. That restriction is the point: whenever you need to come back to the most recent unfinished thing, a stack keeps it right where you can reach it.

How it sits in memory

The usual implementation is an array plus an index top (or a size). Push writes to the next free slot; pop reads the last used slot. When the array fills up it doubles, just like a dynamic array, so push is amortised O(1). A linked list works too: push and pop at the head are O(1), at the cost of a pointer per item.

The call stack and recursion

Your program already uses a stack. Every function call pushes a frame holding its parameters, local variables and where to return to. Returning pops the frame.

This is why any recursive algorithm can be rewritten with an explicit stack, and why very deep recursion crashes with a stack overflow: the call stack has a fixed size, typically a few megabytes.

Expression evaluation

Stacks are how calculators and compilers read expressions.

Postfix (Reverse Polish) notation writes the operator after its operands: 3 4 + 2 * means (3 + 4) × 2. Evaluating it is one pass:

  1. Read a number: push it.
  2. Read an operator: pop the right operand, pop the left operand, push the result.
  3. At the end, the one number left is the answer.
token   stack after
3       [3]
4       [3, 4]
+       [7]          pop 4 and 3, push 3 + 4
2       [7, 2]
*       [14]         pop 2 and 7, push 7 × 2

Bracket matching works the same way: push every opening bracket, and on a closing bracket pop and check that it matches. The string is balanced if every pop matched and the stack is empty at the end.

When to use it

Reach for it when

  • The most recent unfinished thing must be handled first: matching brackets, undo history, back buttons.
  • You're converting recursion to a loop. The call stack becomes an explicit stack.
  • You need the next greater or smaller element. That's the monotonic stack pattern.
  • Evaluating or parsing expressions: postfix evaluation, the shunting-yard algorithm, decoding nested strings.

Think twice when

  • You need the oldest item first. Use a queue.
  • You need to look at or remove items from the middle.

In your language

Notes for Java

  • Use ArrayDeque<Integer> with push, pop and peek. It's faster than the legacy Stack class, which is synchronised and extends Vector.
  • pop() on an empty ArrayDeque throws NoSuchElementException; pollFirst() returns null instead.
  • The JVM's default thread stack is small (often 512 KB to 1 MB), so recursion around 10,000 deep can throw StackOverflowError.

Notes for JavaScript

  • A plain array is a stack: push and pop are O(1). Peek with a[a.length - 1] or a.at(-1).
  • Avoid shift/unshift for stack work; they move every element.
  • Engines limit recursion depth (around 10,000 frames is common), so very deep recursion throws RangeError: Maximum call stack size exceeded.

Notes for TypeScript

  • const stack: number[] = [] with push and pop. pop() returns number | undefined, so the compiler makes you handle the empty case.

Notes for Python

  • A list is a stack: append to push, pop() to pop, stack[-1] to peek. All O(1).
  • collections.deque also works and is thread-safe for appends and pops at either end.
  • Python's default recursion limit is 1,000 frames (sys.getrecursionlimit()), so deep DFS often needs an explicit stack.

Code

The stack is a fixed array with a top index that doubles when full. Two classic uses follow: checking brackets and evaluating a postfix expression.

Common mistakes

  • Popping or peeking an empty stack. Check isEmpty() first.
  • Using a stack when the problem needs first-in, first-out order.
  • In bracket matching, forgetting to check that the stack is empty at the end: (( has no mismatches but is still unbalanced.
  • Deep recursion on large inputs (a 100,000-node linked list or a skewed tree) overflowing the call stack. Use an explicit stack.
