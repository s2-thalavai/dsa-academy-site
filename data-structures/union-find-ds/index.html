Disjoint set (Union-Find)

A disjoint set (union-find) tracks items split into groups that only ever merge. It answers "are these two in the same group?" and merges two groups, each in nearly constant time.

Data structureAdvanced 10 minute read

Picture it. Companies merging. Every employee knows who their boss is, and the CEO is the company's name. To find out whether two people work for the same company, ask each to walk up to their CEO. Merging two companies just means one CEO starts reporting to the other.

What union-find is

Union-find keeps a collection of disjoint sets: every item belongs to exactly one set. It supports two operations:

  • find(x): return the representative (root) of x's set. Two items are in the same set exactly when they have the same root.
  • union(a, b): merge the sets containing a and b.

How it sits in memory

Each set is a tree stored in a parent array: parent[x] is x's parent, and a root is its own parent. Nothing else is needed; there are no child pointers.

The two optimisations

Plain union-find can build long chains, making find O(n). Two small changes fix that:

  1. Union by size (or rank): when merging, attach the smaller tree under the root of the larger one. Tree height then grows only when sizes double, so it stays O(log n) even before compression.
  2. Path compression: during find, point every node you pass straight at the root. Future finds on those nodes take one step.

Together they make each operation run in O(α(n)) amortised time, where α is the inverse Ackermann function. α(n) is at most 4 for any n you could store, so in practice it's constant.

When to use it

Reach for it when

  • Groups merge over time and you ask whether two items are connected: social networks, network connectivity.
  • Counting connected components when edges arrive one at a time.
  • Kruskal's minimum spanning tree: skip an edge if its ends are already connected.
  • Detecting a cycle in an undirected graph: an edge whose ends share a root closes a cycle.

Think twice when

  • Groups need to split apart. Union-find only merges.
  • You need the actual path between two items. Use BFS or DFS.

In your language

Notes for Java

  • Two int[] arrays (parent, size) are all you need. Initialise parent[i] = i.
  • Recursive find with path compression is short but can recurse deeply on the first call; the iterative two-pass version on this page avoids that.

Notes for JavaScript

  • Int32Array for parent and size is compact and fast: const parent = Int32Array.from({ length: n }, (_, i) => i).
  • For string items, map each string to an index with a Map first.

Notes for TypeScript

  • Same as JavaScript. Keep the class small: find, union returning whether a merge happened, and a count of groups.

Notes for Python

  • parent = list(range(n)). Iterative find avoids the recursion limit on long chains.
  • For hashable items that aren't 0..n − 1, use a dict for parent and add items on first sight.

Common mistakes

  • Comparing parent[a] == parent[b] instead of find(a) == find(b). Parents aren't roots until compressed.
  • Forgetting union by size or rank, so chains get long and finds slow down.
  • Decrementing the component count even when the two items were already in the same set.
