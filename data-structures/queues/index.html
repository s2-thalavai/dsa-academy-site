Queues

A queue serves items in the order they arrived: first in, first out (FIFO). You add at the back and remove from the front.

Data structure 11 minute read

Picture it. A ticket counter line. New people join at the back, the person at the front is served next, and nobody cuts in. A deque is the same line with a door at both ends; a priority queue is an emergency room, where the most urgent patient goes first.

What a queue is

A queue supports:

  • enqueue(x) (also offer, push, append): add x at the back.
  • dequeue() (also poll, popleft, shift): remove and return the front.
  • peek(): look at the front without removing it.

Kinds of queue

  • A simple queue is strictly first in, first out.
  • A deque (double-ended queue, said "deck") allows adding and removing at both ends. It can act as a stack or a queue, and it's the core of the monotonic deque pattern.
  • A priority queue always serves the item with the smallest (or largest) key, regardless of arrival order. It's built on a heap, so it has its own page: see Heaps.

How it sits in memory: the circular buffer

A naive array queue removes from index 0 and shifts everything left, which is O(n) per dequeue. A circular buffer avoids that: the front moves forward instead, and the back wraps around to reuse the freed slots.

Keep three numbers: head (index of the front), size (how many items) and the array's capacity. Then:

  • the back slot is (head + size) % capacity
  • dequeue reads data[head], then head = (head + 1) % capacity
  • when size == capacity the buffer is full: either reject the item (a bounded queue) or copy into a buffer twice the size, unrolling the wrap as you go

Queues and breadth-first search

BFS explores a graph in rings: first the start node, then everything one step away, then two steps away. A queue enforces exactly that order, because nodes found earlier are served earlier.

queue = [start]; mark start visited
while queue is not empty:
    node = dequeue
    for each neighbour of node:
        if not visited: mark visited; enqueue neighbour

Each node is enqueued once and each edge examined once, so BFS is O(V + E). See Graph BFS and DFS for the full pattern.

When to use it

Reach for it when

  • Order of arrival matters: task scheduling, request buffers, printing jobs.
  • Breadth-first search. The queue holds the frontier, so nodes are visited level by level.
  • Producer–consumer pipelines, where one side adds work and another takes it.
  • Sliding windows that need both ends: a deque gives O(1) at the front and back.

Think twice when

  • You need the most recent item first. Use a stack.
  • You need random access or search inside the queue.

In your language

Notes for Java

  • Use ArrayDeque<T> for queues and deques: offer/poll/peek for a queue, plus offerFirst, pollLast and friends for a deque. It's a circular buffer inside.
  • LinkedList also implements Queue, but allocates a node per item and is slower.
  • PriorityQueue<T> is a binary min-heap. For a max-heap pass Comparator.reverseOrder().
  • For threads, ArrayBlockingQueue and LinkedBlockingQueue block when empty or full.

Notes for JavaScript

  • array.shift() is O(n), so an array used as a queue gets slow past a few thousand items. Keep a head index instead (queue[head++]) or write a small circular buffer.
  • There's no built-in priority queue; you write a binary heap (see Heaps).

Notes for TypeScript

  • Same as JavaScript. A generic class Queue<T> with a head index or a ring buffer gives you type safety and O(1) dequeue.

Notes for Python

  • Use collections.deque: append and popleft are O(1). Don't use list.pop(0), which is O(n).
  • heapq turns a list into a min-heap priority queue: heappush, heappop.
  • queue.Queue is the thread-safe version for producer–consumer code.

Code

The queue keeps a fixed array, a head index and a size. The tail position is (head + size) % capacity, so slots freed at the front are reused and nothing is ever shifted.

Common mistakes

  • Using list.pop(0) in Python or shift() in JavaScript inside a loop, making BFS O(n²).
  • In a circular buffer, confusing full with empty: both have head == tail. Track a size count to tell them apart.
  • Forgetting to wrap indices with % capacity.
  • In BFS, marking nodes visited when you dequeue instead of when you enqueue, so the same node is queued many times.
