Heaps

A heap keeps the smallest (or largest) item at the top and gives it to you in O(1), while insert and remove take only O(log n). It's a complete binary tree stored in a plain array.

Data structure 13 minute read

Picture it. A tournament bracket where the best player always ends up on top. When a new player arrives they play upward until they lose; when the champion leaves, the last player in is placed on top and plays downward until they find their level.

What a heap is

A binary heap is a binary tree with two rules:

  1. Shape: it's complete. Every level is full except possibly the last, which fills from left to right.
  2. Order: in a min-heap every parent is less than or equal to its children, so the minimum is at the root. A max-heap flips it.

The order rule is weak on purpose. Siblings aren't ordered and the array isn't sorted; only the root is guaranteed. That's enough to find the minimum instantly, and cheap enough to keep up to date in O(log n).

How it sits in memory

Because the tree is complete, it packs into an array with no gaps and no pointers. For index i (counting from 0):

  • left child: 2i + 1
  • right child: 2i + 2
  • parent: (i − 1) / 2, rounded down

Sift up and sift down

  • Insert: append at the end (keeping the shape), then sift up: while the value is smaller than its parent, swap them.
  • Pop: take the root, move the last element to the root, then sift down: while it's larger than its smaller child, swap with that child.

Each sift follows one path between the root and a leaf, and a complete tree with n nodes has height ⌊log₂ n⌋, so both are O(log n).

Heapify in O(n)

To build a heap from an unsorted array, you could insert items one at a time for O(n log n). Bottom-up heapify is faster: sift down every non-leaf, starting from the last one (index n/2 − 1) and working back to the root.

Why O(n)? Half the nodes are leaves and do no work. A quarter sit one level up and sift down at most 1 level, an eighth at most 2, and so on. The total is n/4 × 1 + n/8 × 2 + n/16 × 3 + …, which adds up to less than n.

Priority queues

A priority queue is the abstract idea ("always serve the most important item next") and a heap is the usual way to build one. Each language's built-in priority queue is a binary heap; the language notes below show which way round each one is.

Cost of each operation

OperationTimeWhy
Peek at the min (or max)O(1)It's always at index 0.
InsertO(log n)Sift up along one leaf-to-root path; a complete tree has about log₂ n levels.
Remove the min (pop)O(log n)Move the last item to the root and sift down one path.
Build a heap from n items (heapify)O(n)Most nodes are near the bottom and sift down only a little; the sum of heights is under 2n.
Search for an arbitrary valueO(n)A heap is only partly ordered.
Heap sortO(n log n)Heapify, then pop n times. In place, but not stable.
SpaceO(n)Just the array.

When to use it

Reach for it when

  • You repeatedly need the smallest or largest item: schedulers, event simulations, Dijkstra's algorithm.
  • You want the top K items from a stream without sorting everything (a size-K heap is O(n log k)).
  • You merge K sorted lists or files.
  • You track a running median (two heaps).

Think twice when

  • You need everything in sorted order once. Just sort.
  • You need to search for or delete arbitrary items often. Use a balanced BST.

In your language

Notes for Java

  • PriorityQueue<Integer> is a min-heap: offer, poll, peek. For a max-heap: new PriorityQueue<>(Comparator.reverseOrder()).
  • Order objects with a comparator: new PriorityQueue<>((a, b) -> a[1] - b[1]). Prefer Integer.compare(a[1], b[1]), since subtraction can overflow.
  • remove(Object) is O(n). new PriorityQueue<>(collection) heapifies in O(n).

Notes for JavaScript

  • No built-in heap. Write a small class (like the one on this page) with push, pop and peek, and pass a comparator for custom ordering.
  • Sorting an array after every insert is O(n log n) per operation, so don't use that as a priority queue.

Notes for TypeScript

  • Make the heap generic with a comparator field, less: (a: T, b: T) => boolean, so one class serves numbers, tuples and objects.
  • The files on this site assign fields in the constructor body instead of using parameter properties (constructor(private less: ...)), because Node runs TypeScript by stripping types and doesn't support that shorthand.

Notes for Python

  • heapq works on a plain list: heappush(h, x), heappop(h), h[0] to peek, heapify(h) in O(n).
  • It's a min-heap only. For a max-heap push -x. For objects push tuples (priority, counter, item), where the counter breaks ties so items never get compared.
  • heapq.nlargest(k, xs) and nsmallest solve top-K directly.

Common mistakes

  • Using a min-heap when you need a max-heap, or the other way round. Write down which one before coding.
  • Overflowing a subtraction comparator in Java with large or negative values.
  • Thinking the heap array is sorted. Only the root is guaranteed; [1, 3, 2] is a valid heap.
  • Building a heap by inserting one at a time (O(n log n)) when heapify (O(n)) would do.
  • In Python, pushing tuples whose second element isn't comparable, so ties raise a TypeError.
