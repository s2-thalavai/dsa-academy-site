Two Sum II, sorted input

medium Two pointers Arrays

Open LeetCode 167 (opens in a new tab)

The problem in plain words

You get a list of whole numbers sorted from smallest to largest, and a target. Exactly one pair of different positions holds numbers that add up to the target. Return those two positions, counting from 1, smaller position first. You may use only a constant amount of extra memory.

Example: in [2, 7, 11, 15] with target 9, the numbers 2 and 7 add up to 9. They sit at positions 1 and 2, so the answer is [1, 2].

Brute force first

Try every pair. For each position i, check every later position j and see if numbers[i] + numbers[j] equals the target.

This is correct, but with n numbers there are about n²/2 pairs, so it takes O(n²) time. It throws away the one thing the problem gives us for free: the order.

The optimal idea

Put one pointer on the smallest number and one on the largest, then look at their sum.

  • Sum too small? The left number can't be part of the answer. Even paired with the largest number left, it falls short. Move the left pointer right.
  • Sum too big? The right number can't be part of the answer. Even paired with the smallest number left, it overshoots. Move the right pointer left.
  • Sum equal? Done.

Every step rules out one number for good, so the pointers meet after at most n − 1 steps. That is the whole of the Two Pointers pattern: sorted order lets you discard a candidate with a single comparison.

Two pointersO(n)O(1)

Each loop pass moves one pointer one step inward, and they stop when they meet, so the loop runs at most n − 1 times. Only two index variables are stored, whatever the input size.

Edge cases

  • Only two numbers: the pointers start on the answer, so the loop runs once.
  • Negative numbers and zero: nothing changes, because the argument only relies on the order.
  • Repeated values, such as [2, 2] for target 4: the pointers are distinct indices, so the same value can be used twice.
  • The answer is 1-based. Returning left and right without adding 1 is the most common bug.

Follow-up questions

  • What if the array is not sorted? Sorting costs O(n log n) and loses the original positions. A hash map gives O(n) time with O(n) space.
  • What if you need every pair, not just one? Keep going after a match, and skip repeated values on both sides.
  • How does this extend to three numbers (LeetCode 15)? Fix one number, then run this same loop on the rest.
