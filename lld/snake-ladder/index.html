Snake and ladder

A board game is a good test of clean object design: a board that knows its jumps, players that know their square, dice you can swap for testing, and a game loop that owns turn order and the winning rule.

Low-level design

Picture it. The board is the rule book, the dice are a referee you can replace with a scripted one for practice, and the game is the host who calls each player in turn.

Requirements

Functional

  • A board of N squares with snakes (down) and ladders (up).
  • Players take turns in a fixed order, rolling one die.
  • A roll that would pass the last square is lost; the player stays put.
  • The first player to land exactly on the last square wins.
  • Bonus: the fewest rolls needed to finish this board (LeetCode 909).

Non-functional

  • Deterministic tests: the dice are injected.
  • Invalid boards (a jump from the last square, two jumps from one square) are rejected when built.

Entities and relationships

  • Board owns the geometry and validates jumps as they're added: a jump can't start on square 0 or the last square, and a square can't have two jumps. destination(sq) returns where a player who lands on sq ends up.
  • Game owns the rules: turn order (a queue: take the front, play, put back), the exact-landing rule and the win check.
  • Dice is an interface so tests use ScriptedDice and the real game uses RandomDice. Two dice, or a "six gives another turn" rule, are a new class or a small rule change, not a rewrite.

Design patterns used

  • Strategy / dependency injection: the dice are passed in.
  • Iterator-like turn queue: a queue gives round-robin order for any number of players.
  • Validation at construction: invalid boards fail fast, so the game loop never sees one.

How a request flows

Fewest rolls (LeetCode 909) is breadth-first search over squares: from each square try rolls 1–6, follow any jump, and the first time you reach the last square, the BFS level is the answer.

Cost of each operation

OperationTimeWhy
One turnO(1)A roll, a map lookup and a queue operation.
Fewest rolls (BFS)O(6 × N)Each square is visited once with six moves.

Code

A 30-square board, two players and scripted dice, so the whole game prints the same way every time.

Common mistakes

  • Putting the move logic in Player, so players need to know about the board and the rules.
  • Hard-coding Math.random() inside the game loop, making it untestable.
  • Letting a player move past the last square.
  • Following jumps repeatedly in a chain without deciding whether that's a rule.

Interview follow-ups

  • Several dice, and a rule that three sixes in a row sends you back to the start.
  • Save and resume a game.
  • Multiplayer over the network: who owns the dice?
  • Generate random boards that are always winnable.
