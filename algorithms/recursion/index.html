Recursion

A recursive function solves a problem by calling itself on a smaller version of the same problem, until it reaches a case small enough to answer directly.

Technique 12 minute read

Picture it. Russian nesting dolls. To find the smallest doll you open one, and inside is the same task with a smaller doll. You stop when a doll doesn't open: that's the base case. Then you close them back up in reverse order, which is the return trip.

The two parts of every recursive function

  1. Base case: an input small enough to answer directly, without recursing. factorial(0) = 1, an empty list, a null tree node.
  2. Recursive case: break the input into something smaller, call yourself on it, and combine the result. factorial(n) = n × factorial(n − 1).

If every recursive call moves closer to a base case, the recursion stops.

Trust the recursive call

The hardest habit to build is not tracing every level in your head. Instead, assume the function already works for smaller inputs (the "recursive leap of faith"), and only check two things: the base case is right, and the recursive case builds the right answer from the smaller answers. That's mathematical induction, applied to code.

maxDepth(node):
    if node is null: return 0                                   ← base case
    return 1 + max(maxDepth(node.left), maxDepth(node.right))   ← trust both calls

What happens on the call stack

Each call pushes a frame with its own copy of the parameters and local variables. factorial(3) pushes frames for 3, 2, 1 and 0. The base case returns 1, then each waiting frame multiplies and returns in turn. The stack holds n frames at its deepest, so the space cost is O(n) even though no data structure was created.

Overlapping subproblems and memoisation

When the same arguments come up again and again, store each answer the first time you compute it and look it up afterwards. That's memoisation, and it's the top-down form of dynamic programming. It turns Fibonacci from O(2ⁿ) to O(n).

Recursion vs iteration

Any recursion can be rewritten as a loop with an explicit stack, and simple "call once then return" recursion can become a plain loop. Recursion is often clearer for trees and backtracking; loops are safer for deep inputs and avoid function-call overhead.

When to use it

Reach for it when

  • The data is recursive itself: trees, nested lists, file systems, JSON.
  • The problem splits into smaller copies of itself: divide and conquer, dynamic programming.
  • You explore choices and undo them: backtracking.

Think twice when

  • The depth could reach tens of thousands. Use a loop or an explicit stack to avoid stack overflow.
  • A simple loop does the job. Iteration is usually faster and uses O(1) stack.

In your language

Notes for Java

  • The default thread stack fits roughly 10,000 to 20,000 frames, depending on frame size. Deeper recursion throws StackOverflowError.
  • Java doesn't eliminate tail calls, so tail recursion doesn't save stack.
  • Memoise with a long[] sized to the input, or HashMap<Long, Long> for sparse keys.

Notes for JavaScript

  • Engines allow roughly 10,000 frames before RangeError: Maximum call stack size exceeded. Tail-call optimisation isn't implemented in V8.
  • Memoise with a Map, or a closure: const memo = new Map(); function f(n) { if (memo.has(n)) return memo.get(n); ... }.

Notes for TypeScript

  • Annotate return types on recursive functions (function fib(n: number): number); inference can't always resolve them.

Notes for Python

  • The recursion limit is 1,000 by default. sys.setrecursionlimit raises it, but the C stack can still overflow; prefer iteration for deep recursion.
  • @functools.cache (or lru_cache(maxsize=None)) memoises a function in one line.

Common mistakes

  • No base case, or a base case that's never reached, so the recursion never stops.
  • The recursive call doesn't make the problem smaller (for example, calling f(n) from f(n) on some path).
  • Forgetting to return the recursive call's result: f(n - 1) instead of return f(n - 1).
  • Recomputing overlapping subproblems. Memoise when the same arguments come up again.
  • Mutating a shared list or array and forgetting to undo it before returning.
