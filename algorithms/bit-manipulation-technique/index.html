Bit manipulation

Integers are rows of bits. Bitwise operators work on every bit at once, which turns some loops into a single instruction and lets one integer stand for a whole set of yes/no choices.

Technique 12 minute read

Picture it. A row of light switches. AND keeps a light on only if both rows have it on; OR turns it on if either does; XOR turns it on if exactly one does. Shifting slides the whole row left or right, doubling or halving the number it spells.

Binary in one minute

Bit k of a number is worth 2ᵏ. Thirteen is 8 + 4 + 1, so its bits from high to low are 1101. Negative numbers use two's complement: −x is ~x + 1, which is why x & −x isolates the lowest set bit.

The operators

Operator Reads as Typical use
a & b AND: 1 where both are 1 test or clear bits with a mask
a | b OR: 1 where either is 1 set bits
a ^ b XOR: 1 where they differ toggle bits, cancel pairs
~a NOT: flip every bit build an inverse mask
a << k shift left multiply by 2ᵏ, build masks 1 << k
a >> k shift right divide by 2ᵏ (rounding down)

Tricks worth knowing by heart

  • Test bit k: (x >> k) & 1.
  • Set, clear, toggle bit k: x | (1 << k), x & ~(1 << k), x ^ (1 << k).
  • Clear the lowest set bit: x & (x − 1). Repeating it counts set bits.
  • Power of two: x > 0 && (x & (x − 1)) == 0.
  • XOR cancels pairs: a ^ a = 0 and a ^ 0 = a, so XOR-ing a list where everything appears twice except one value leaves that value.
  • Subsets as masks: for n items, the integers 0 to 2ⁿ − 1 are all the subsets. Bit i of the mask says whether item i is in.

Cost of each operation

OperationTimeWhy
AND, OR, XOR, NOT, shiftsO(1)One machine instruction on a fixed-width integer.
Count set bits (popcount)O(number of set bits)x &= x - 1 clears one set bit per step. Hardware does it in O(1).
Enumerate all subsets of n items as masksO(2ⁿ × n)2ⁿ masks, n bits to read each.
Bitmask DP over subsetsO(2ⁿ × n) states × transitionsFeasible up to about n = 20.

When to use it

Reach for it when

  • The problem mentions XOR, powers of two, binary representation or bit counts.
  • Finding the element that appears an odd number of times (XOR cancels pairs).
  • Representing a small set (up to 32 or 64 items) as one integer: visited states, subsets, permissions.

Think twice when

  • Readability matters more than a constant-factor gain. x * 2 is clearer than x << 1, and compilers optimise it anyway.

In your language

Notes for Java

  • int is 32-bit and long 64-bit, both signed two's complement. >> keeps the sign; >>> fills with zeros.
  • Integer.bitCount, Integer.highestOneBit, Integer.numberOfTrailingZeros and Long.bitCount are built in.
  • Write 1L << 40, not 1 << 40, for shifts past bit 31.

Notes for JavaScript

  • Bitwise operators convert numbers to 32-bit signed integers, so 2 ** 32 | 0 is 0. Use BigInt (1n << 40n) for wider masks.
  • >>> is the unsigned right shift. x >>> 0 reinterprets a negative 32-bit value as unsigned.

Notes for TypeScript

  • Same 32-bit rules as JavaScript. A number used as a mask works up to 31 items safely.

Notes for Python

  • Integers are unbounded, so there's no overflow and ~x is -x - 1. Mask to 32 bits with x & 0xFFFFFFFF when emulating fixed-width arithmetic.
  • bin(x), x.bit_count() (3.10+) and x.bit_length() are built in.

Code

Common mistakes

  • Operator precedence: in Java, JavaScript and C, x & 1 == 0 parses as x & (1 == 0). Parenthesise: (x & 1) == 0.
  • Shifting past the width of the type, such as 1 << 32 for a 32-bit int.
  • Forgetting that right-shifting a negative number keeps the sign bit (>>).
  • Treating 0 as a power of two: x & (x - 1) == 0 is true for 0, so also check x > 0.
