Greedy

A greedy algorithm builds its answer one step at a time, always taking the choice that looks best right now and never going back. When it works it's simple and fast; the hard part is proving it works.

Technique 12 minute read

Picture it. Giving change with the largest coin that fits, over and over. With rupee or dollar coins that gives the fewest coins. With coins of 1, 3 and 4, paying 6 that way takes 4 + 1 + 1, while 3 + 3 uses two. Greedy is right only when the problem's structure guarantees it.

How greedy works

At each step, make the choice that's best by some simple rule (earliest finish, largest value, cheapest edge), commit to it, and move on. There's no backtracking and no table of subproblems. That's why greedy algorithms are usually short and run in O(n) or O(n log n).

Classic example: activity selection

Given activities with start and end times, choose as many as possible with no overlaps.

Greedy rule: pick the activity that ends first, discard everything that overlaps it, and repeat. Choosing by earliest start or shortest length both fail on some inputs; earliest end doesn't.

Proving a greedy choice: the exchange argument

Suppose an optimal answer doesn't include the activity with the earliest end, g. Its first activity, o, ends at or after g ends. Swap o for g: nothing else overlaps g that didn't overlap o, so the answer is still valid and still the same size. So some optimal answer starts with g, and the same argument repeats on what's left.

Interviewers rarely want a formal proof, but they do want you to say why the greedy choice is safe, or to show a counterexample when it isn't.

When greedy fails

Coins {1, 3, 4}, amount 6. Greedy takes 4, then 1, then 1: three coins. The optimum is 3 + 3: two coins. Taking the biggest coin first isn't safe in this system, so you need dynamic programming, which tries every last coin.

Cost of each operation

OperationTimeWhy
Typical greedy: sort, then one passO(n log n)The sort dominates; the pass is O(n).
Greedy with a heap (repeatedly take the best)O(n log n)Each push or pop is O(log n).
Greedy single pass (jump game, gas station)O(n)Track one running quantity.
SpaceO(1) to O(n)Usually just a few variables, or a heap.

When to use it

Reach for it when

  • Interval scheduling: maximise non-overlapping meetings, minimise rooms or arrows.
  • A local choice can be shown never to hurt: the exchange argument works.
  • Huffman coding, minimum spanning trees (Prim, Kruskal) and Dijkstra's algorithm are all greedy.

Think twice when

  • A small counterexample breaks it, like coins 1, 3, 4. Use dynamic programming.
  • Choices affect the options available later in complicated ways (0/1 knapsack).

In your language

Notes for Java

  • Sort intervals by end time with Arrays.sort(iv, (a, b) -> Integer.compare(a[1], b[1])).
  • PriorityQueue is the go-to for "always take the current best" greedy loops.

Notes for JavaScript

  • intervals.sort((a, b) => a[1] - b[1]) sorts by end. Remember the comparator.

Notes for TypeScript

  • Type intervals as [number, number][] so destructuring const [start, end] = iv is checked.

Notes for Python

  • intervals.sort(key=lambda iv: iv[1]) sorts by end. heapq covers the priority-based greedy loops.

Common mistakes

  • Assuming greedy works without checking a counterexample. Try small inputs by hand first.
  • Sorting by the wrong key: start time instead of end time for maximum non-overlapping intervals.
  • Using > where the problem allows touching intervals (>=), or the other way round.
