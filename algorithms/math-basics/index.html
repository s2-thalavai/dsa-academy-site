Math basics

A small toolkit of number theory shows up again and again: greatest common divisors, primes, modular arithmetic and fast exponentiation. Each one replaces a slow loop with a fast formula.

Technique 14 minute read

Picture it. A 12-hour clock is modular arithmetic: 9 o'clock plus 5 hours is 2 o'clock, because you only keep the remainder after 12. Problems that say "return the answer modulo 10⁹ + 7" use the same idea to keep huge numbers small.

Greatest common divisor

Euclid's observation: any number that divides both a and b also divides a mod b. So gcd(a, b) = gcd(b, a mod b), and gcd(a, 0) = a. The numbers shrink fast, giving O(log min(a, b)) steps. The least common multiple follows: lcm(a, b) = a / gcd(a, b) × b.

Primes and the sieve

To test one number, try dividing by 2, 3, 4, … up to √n. If n = p × q then one of p, q is at most √n, so there's no need to go further.

Modular arithmetic

When answers get huge, problems ask for them modulo a prime M, usually 10⁹ + 7. The rules let you reduce at every step:

  • (a + b) mod M = ((a mod M) + (b mod M)) mod M
  • (a × b) mod M = ((a mod M) × (b mod M)) mod M
  • (a − b) mod M = ((a − b) mod M + M) mod M, so the result is never negative

Division is the exception. To divide by b, multiply by its modular inverse b⁻¹, the number with b × b⁻¹ ≡ 1 (mod M). When M is prime, Fermat's little theorem gives b⁻¹ = bᴹ⁻² mod M.

Fast power

Computing aᵇ with b multiplications is too slow when b is 10¹⁸. Instead, use the binary digits of b:

result = 1
while b > 0:
    if b is odd: result = result × a mod M
    a = a × a mod M
    b = b / 2

Each loop handles one bit of b, so it runs about 60 times even for b = 10¹⁸.

When to use it

Reach for it when

  • The answer must be reported modulo a large prime (usually 10⁹ + 7).
  • Divisibility, common factors or fractions in lowest terms (gcd, lcm).
  • Counting primes or factorising many numbers (sieve).
  • Raising to huge powers, or counting combinations under a modulus.

Think twice when

  • Floating-point is fine and exact integers aren't needed.

In your language

Notes for Java

  • a % b keeps the sign of a: -7 % 3 is -1. Use Math.floorMod(-7, 3) (gives 2) for a true modulus.
  • Multiply two values below 10⁹ + 7 in long, never int: the product reaches about 10¹⁸.
  • BigInteger.modPow and modInverse exist for arbitrary sizes.

Notes for JavaScript

  • Numbers are doubles: products above 2⁵³ (about 9 × 10¹⁵) lose precision. Two values near 10⁹ multiply to 10¹⁸, so use BigInt (10n ** 9n + 7n) for modular multiplication.
  • % keeps the sign of the dividend, like Java: use ((a % m) + m) % m.

Notes for TypeScript

  • Type BigInt values as bigint; you can't mix bigint and number in arithmetic without converting.

Notes for Python

  • Integers are arbitrary precision, so overflow isn't a concern, and % always returns a non-negative result for a positive modulus.
  • pow(a, b, m) is fast modular exponentiation; pow(a, -1, m) (3.8+) is the modular inverse; math.gcd, math.lcm and math.comb are built in.

Code

JavaScript and TypeScript use BigInt for modular arithmetic, because two numbers near 10⁹ multiply past the precision of a double.

Common mistakes

  • Overflow from multiplying before taking the modulus. Reduce after every multiplication.
  • Negative results from % in Java and JavaScript after a subtraction.
  • Using Fermat's inverse with a modulus that isn't prime.
  • Dividing under a modulus. Multiply by the modular inverse instead.
  • Computing lcm as a * b / gcd(a, b), which can overflow; use a / gcd(a, b) * b.
