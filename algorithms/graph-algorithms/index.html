Graph algorithms

The core graph algorithms answer a handful of questions: what can I reach (BFS, DFS), in what order can I do things (topological sort), what's the cheapest route (Dijkstra, Bellman-Ford, Floyd-Warshall), and what's the cheapest way to connect everything (Prim, Kruskal).

Technique 22 minute read

Picture it. A delivery company. BFS is asking which towns are reachable in k hops. Topological sort is loading the truck so every package needed for another comes off first. Dijkstra is the satnav. Prim and Kruskal are laying the least cable that still connects every town.

BFS and DFS: the two traversals

  • Breadth-first search uses a queue and visits nodes in order of distance in hops. In an unweighted graph, the first time BFS reaches a node is along a shortest path.
  • Depth-first search uses recursion or a stack and goes as deep as possible before backing up. It's the basis of cycle detection, connected components, topological sort and backtracking.

Both are O(V + E). Their code is on the Graphs page.

Topological sort

A topological order of a DAG lists every node before all the nodes it points to. Kahn's algorithm: count each node's incoming edges (in-degree), start a queue with every node whose in-degree is 0, and repeatedly output a node and decrement its neighbours, enqueuing any that reach 0. If fewer than V nodes come out, the graph has a cycle and no order exists.

Shortest paths

Relaxation is the shared idea: if going to u and then along edge u → v beats the best known distance to v, update it.

  • Dijkstra always expands the unsettled node with the smallest distance, using a min-heap. With non-negative weights, that distance can never improve later, so each node is settled once.
  • Bellman-Ford relaxes every edge, V − 1 times. Any shortest path has at most V − 1 edges, so that's enough. If a V-th round still improves something, there's a negative cycle.
  • Floyd-Warshall computes all pairs: for each middle node k, check whether i → k → j beats i → j. Three loops, k outermost.

Minimum spanning trees

A spanning tree connects all V nodes with V − 1 edges. The minimum spanning tree has the smallest total weight. Both classic algorithms are greedy, and both rely on the cut property: the cheapest edge crossing any split of the nodes is safe to take.

  • Kruskal: sort edges by weight; take each edge whose ends are in different components (checked with union-find).
  • Prim: grow one tree from any node; repeatedly add the cheapest edge from the tree to a node outside it (using a min-heap).

Cost of each operation

OperationTimeWhy
BFS, DFSO(V + E)Every node and edge is handled once. BFS gives shortest paths when every edge weighs the same.
Topological sort (Kahn or DFS)O(V + E)Each edge decrements one in-degree once.
Dijkstra with a binary heapO((V + E) log V)Each edge may push a heap entry; each pop is O(log V). Needs non-negative weights.
Bellman-FordO(V × E)V − 1 rounds of relaxing every edge. Handles negative weights and detects negative cycles.
Floyd-WarshallO(V³) time, O(V²) spaceThree nested loops over an adjacency matrix: all pairs at once.
Prim with a heapO(E log V)Grow one tree, always adding the cheapest edge leaving it.
Kruskal with union-findO(E log E)Sort the edges, then add each one that joins two different components.

When to use it

Reach for it when

  • BFS: fewest steps in an unweighted graph or grid. DFS: reachability, components, cycle detection, backtracking over a graph.
  • Topological sort: ordering tasks with prerequisites, detecting cycles in a directed graph.
  • Dijkstra: shortest paths from one source with non-negative weights. Bellman-Ford: when weights can be negative, or with a limit on the number of edges.
  • Floyd-Warshall: all-pairs distances on small graphs (V up to about 400).
  • Prim or Kruskal: the cheapest set of edges connecting all nodes (minimum spanning tree).

Think twice when

  • Dijkstra with negative edges: it can settle a node too early and return wrong distances.
  • Floyd-Warshall on large graphs: V³ is 10¹⁵ at V = 10⁵.

In your language

Notes for Java

  • Dijkstra: PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1])) holding {node, dist}. Skip stale entries whose distance is larger than the recorded one.
  • Use long distances when weights × path length can pass 2³¹.

Notes for JavaScript

  • There's no built-in heap, so Dijkstra needs a small binary heap (see Heaps). An O(V²) "scan for the minimum" version is fine for V up to a few thousand.
  • Use Infinity for unreachable distances; it compares correctly with numbers.

Notes for TypeScript

  • Type weighted adjacency lists as Array<Array<[to: number, weight: number]>>.

Notes for Python

  • heapq with (dist, node) tuples gives Dijkstra in about 12 lines. Skip popped entries where d > dist[node].
  • float("inf") for unreachable; math.inf reads well too.

Common mistakes

  • Running Dijkstra on graphs with negative edges.
  • Not skipping stale heap entries in Dijkstra, which wastes time (lazy deletion is the norm).
  • In topological sort, forgetting to check that every node was output: if not, the graph has a cycle.
  • Using Integer.MAX_VALUE as infinity and then adding a weight to it, which overflows.
  • Forgetting that an undirected edge must be added in both directions for Prim.
