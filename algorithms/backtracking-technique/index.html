Backtracking

Backtracking builds a solution one choice at a time and abandons a partial solution as soon as it can't lead anywhere useful, then undoes the last choice and tries the next one.

Technique 13 minute read

Picture it. Finding your way through a maze. At each fork you pick a path and keep a hand on the wall. When you hit a dead end, you walk back to the last fork and take the next path you haven't tried.

The template

backtrack(path, choices):
    if path is a complete solution: record a copy; return
    for each choice that is still allowed:
        make the choice          (add to path, mark as used)
        backtrack(path, remaining choices)
        undo the choice          (remove from path, unmark)

Everything else is detail: what counts as complete, which choices are allowed, and how early you can prune.

The decision tree

It helps to draw the tree for a tiny input before coding. The depth is the number of decisions; the branching factor is the number of options per decision. Together they give the complexity: 2 options at each of n levels is 2ⁿ leaves; n, then n − 1, then n − 2 options is n! leaves.

Pruning

Pruning means stopping a branch as soon as it can't succeed. In combination sum, once the running total exceeds the target, deeper choices only make it bigger, so return immediately. In N-Queens, a queen that shares a column or diagonal with an earlier one rules out the whole subtree below it. Good pruning is the difference between a backtracking solution that passes and one that times out.

Cost of each operation

OperationTimeWhy
All subsets of n itemsO(2ⁿ × n)2ⁿ subsets, O(n) to copy each one out.
All permutations of n itemsO(n! × n)n! orderings, O(n) to copy each.
N-Queensunder O(n!)Pruning by column and diagonals cuts most branches early.
SpaceO(n) besides the outputThe current path and the recursion stack are as deep as the number of choices.

When to use it

Reach for it when

  • The problem asks for all (or any valid) combinations, subsets, permutations, partitions or placements.
  • Constraints let you reject a partial solution early: Sudoku, N-Queens, word search.
  • Input sizes are small, around 10 to 20, which is the judge's hint that exponential search is expected.

Think twice when

  • Only a count or an optimum is needed and subproblems overlap. Dynamic programming is faster.
  • n is large; 2ⁿ is hopeless past about 30.

In your language

Notes for Java

  • Keep one List<Integer> path and add/remove(path.size() - 1) around the recursive call. Copy it with new ArrayList<>(path) when you record a result.
  • A boolean[] used array tracks taken items for permutations.

Notes for JavaScript

  • path.push(x), recurse, path.pop(). Record results with [...path], or every result ends up pointing at the same (empty) array.

Notes for TypeScript

  • Type the result as number[][] and the path as number[]. The copy-on-record rule applies here too.

Notes for Python

  • path.append(x), recurse, path.pop(). Record path[:] or list(path), not path itself.
  • itertools.combinations, permutations and product generate the standard cases directly, but interviews expect the hand-written version.

Code

Every function follows the same template: check whether the path is complete, loop over the choices, choose, recurse, undo.

Common mistakes

  • Recording path instead of a copy, so every saved result changes later.
  • Forgetting to undo the choice after the recursive call.
  • Generating duplicates when the input has repeated values. Sort first and skip equal values at the same depth.
  • Not pruning, so the search explores branches that can never succeed.
