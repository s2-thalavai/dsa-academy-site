Searching

Searching finds a value, or the place it would go. Linear search checks everything; binary search uses sorted order to halve the range on every look.

Technique 13 minute read

Picture it. Guessing a number between 1 and 100 when you're told "higher" or "lower". Guessing 1, 2, 3… takes up to 100 tries. Guessing the middle every time takes at most 7, because each answer rules out half of what's left.

Linear search

Check each item until you find the target or run out. It's O(n), needs no preparation and works on anything you can iterate: unsorted arrays, linked lists, streams. For one search on unsorted data it's the right choice.

Binary search

On sorted data you can do far better. Look at the middle element:

  • if it's the target, you're done
  • if it's too small, the target can only be to the right: discard the left half
  • if it's too big, discard the right half

After k steps, n / 2ᵏ items remain. The search ends when one item is left, so k is about log₂ n: 20 steps for a million items, 30 for a billion.

Lower and upper bounds

Often you don't want "is x here?" but "where does x start?" or "where would x go?". The lower bound is the first index with a[i] >= x; the upper bound is the first index with a[i] > x. Their difference counts how many copies of x there are.

The pattern is binary search for the first position where a yes/no condition becomes true, keeping hi as a candidate answer:

lo = 0, hi = n                 ← hi = n means "not found yet"
while lo < hi:
    mid = lo + (hi − lo) / 2
    if a[mid] >= x: hi = mid   ← mid might be the answer; keep it
    else:           lo = mid + 1
return lo

Binary search on the answer

Some problems ask for the smallest value that makes something possible: the minimum capacity, the slowest speed, the shortest time. If you can check whether a given value works, and every larger value also works, then the "works" answers form a run of no…no yes…yes over the possible values. Binary search finds the first yes.

Example: piles of bananas [3, 6, 7, 11] must be eaten in 8 hours, one pile at a time, at most k bananas per hour. Speed 4 works (1 + 2 + 2 + 3 = 8 hours); speed 3 doesn't (10 hours). Searching speeds 1 to 11 finds 4 in four checks.

Cost of each operation

OperationTimeWhy
Linear searchO(n)Check items one by one. Works on any data, sorted or not.
Binary searchO(log n)Each step halves the range: after k steps n / 2ᵏ items remain, so k = log₂ n.
Lower or upper boundO(log n)Binary search for the first position where a condition becomes true.
Binary search on the answerO(log(range) × cost of check)Search the space of possible answers, testing each guess with a feasibility check.
SpaceO(1)Iterative versions store two or three indices. Recursive ones use O(log n) stack.

When to use it

Reach for it when

  • The data is sorted, or you can sort it once and search many times.
  • You need the first or last position meeting a condition (first bad version, insertion point).
  • The question asks for the minimum or maximum value that makes something possible, and feasibility is monotonic: if 5 works, 6 works too.

Think twice when

  • The data is unsorted and you search once. Sorting costs O(n log n), more than a single linear scan.
  • You need exact-key lookups many times on unsorted data. A hash set is O(1).

In your language

Notes for Java

  • Arrays.binarySearch(a, key) returns the index if found, otherwise -(insertionPoint) - 1. With duplicates it returns some matching index, not necessarily the first.
  • Collections.binarySearch works on sorted lists. TreeMap.floorKey and ceilingKey do bound searches on a tree.
  • Compute the middle as lo + (hi - lo) / 2; (lo + hi) / 2 overflows when both are near Integer.MAX_VALUE.

Notes for JavaScript

  • There's no built-in binary search on arrays; write it. indexOf and includes are linear.
  • Use lo + ((hi - lo) >> 1) or Math.floor((lo + hi) / 2). Numbers are doubles, so overflow isn't a concern below 2⁵³.

Notes for TypeScript

  • A generic lowerBound<T>(a: readonly T[], pred: (x: T) => boolean): number covers most bound searches with one function.

Notes for Python

  • bisect.bisect_left(a, x) is the lower bound (first index with a[i] >= x); bisect_right is the upper bound. Both are O(log n).
  • Since Python 3.10 both take a key= argument.
  • x in list is linear; use a set for membership.

Common mistakes

  • Off-by-one in the loop condition. With hi = n − 1 use while lo <= hi; with hi = n use while lo < hi and hi = mid.
  • Infinite loops from lo = mid instead of lo = mid + 1 when mid rounds down.
  • Overflow in (lo + hi) / 2 in Java and C++.
  • Running binary search on unsorted data.
  • In binary search on the answer, getting the monotonic direction backwards.
